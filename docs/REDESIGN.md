## 1. 审美定位

**一句话**：像一本团队内部的工作手册。纸面干净，墨蓝色压得住，读起来不累，一线打开会觉得「这是我们公司自己的工具」，而不是一个借来的课程站。

| 取舍 | 做法 | 为什么 |
|---|---|---|
| 保留骨架 | 顶栏、导航项、术语卡片网格、左侧目录、暗色模式都不动 | Will 喜欢现在的整体结构；冻结规则也不允许改导航和课程页 |
| 换掉签名 | 克莱因蓝、8 色主题点、首页的网格光晕背景、首屏直接是术语目录 | 这几处是「一眼认出原站」的主要来源 |
| 气质 | 暖白纸面、深墨蓝单一主色、细边框代替阴影、中文系统字 | 团队学习要「清楚、可信」，不需要营销感 |

### 参考了哪几家（只提炼原则，不照搬任何一家）

资料来自授权资源包 `R-国内外设计系统DESIGN`，用 grep 抽取色板和原则，没有复制任何品牌的字体、图形或文案。

| 来源 | 借了什么原则 | 没借什么 |
|---|---|---|
| Notion | 暖中性纸面（奶白底 + 暖灰字），让大段阅读不刺眼 | 深夜蓝大色块首屏、Lyon 衬线字 |
| Stripe | 「近乎单色 + 只有一个饱和色承担行动」；主文字用深蓝黑而不是纯黑 | 渐变光晕、sohne 字体、细字重大标题 |
| Atlassian | 团队工具的信息密度；主色只给按钮、链接、焦点这类「可操作」元素 | 胶囊大圆角按钮、彩色插画带 |

## 2. Token 调整

Token 就是「全站共用的设计变量」：底色、文字色、边框、主色、圆角、阴影。改一处，全站跟着变，所以正式改版主要靠改 token，而不是一页页改样式。

样稿把新 token 写在 `src/app/globals.css` 末尾的「定制 token」块里，覆盖原站 `vibehub.css` 的同名变量，原文件一个字不改。撤回就是删掉这一块。

### 2.1 浅色

| 变量 | 原站 | 样稿 | 说明 |
|---|---|---|---|
| `--bg` | `#ffffff` | `#fbfaf8` | 暖白纸面 |
| `--bg-soft` | `#fafafa` | `#f4f2ee` | 次级底色（标签、空状态） |
| `--bg-hover` | `#f4f4f5` | `#eeebe6` | 悬停 |
| `--text` | `#18181b` | `#1d1f24` | 深墨色，偏一点蓝 |
| `--text-2` | `#52525b` | `#4f4b45` | 暖灰正文 |
| `--text-3` | `#686e79` | `#6b665f` | 辅助字，对 `--bg` 对比度约 5.5:1 |
| `--border` | `#e4e4e7` | `#e6e2db` | 暖灰细线 |
| `--border-hover` | `#d9dbe0` | `#d5d0c7` | |
| `--border-light` | `#f0f0f2` | `#efece6` | |
| `--shadow-card` | 两层阴影 | 一条 1px 发丝影 | 靠边框分层，不靠阴影 |
| 默认主色 | 克莱因蓝 `#3559d8` | 墨蓝 `#1f4e8c` | 见 2.3 |

### 2.2 深色

深色改成暖黑（`#1a1917` 底、`#dedad3` 字），和浅色的纸面气质一致；原站是冷灰黑 `#1b1d21`。

### 2.3 主题色：8 色换成自有 4 色

`src/lib/vibehub/theme.ts` 只改颜色值和名字，顶栏的主题点组件不动。

| id | 名字 | 浅色 | 深色 |
|---|---|---|---|
| `ink`（默认） | 墨蓝 | `#1f4e8c` | `#8fb0e0` |
| `pine` | 松绿 | `#2f6b52` | `#86c7a6` |
| `clay` | 陶土 | `#a4502f` | `#e4a07f` |
| `graphite` | 石墨 | `#4a4f57` | `#b9bec6` |

老用户浏览器里存的是 `klein`、`violet` 这类旧 id，查不到时会自动回到默认墨蓝（原有兜底逻辑），不用迁移。

### 2.4 字体与字号

- 正文仍用系统中文字（苹方 / 微软雅黑），不引入新字体，不装依赖。
- 原站的 Manrope 只用在页脚巨型字标和少量数字上；样稿不动页脚，列入正式改版。
- 首页标题：`clamp(28px, 3.4vw, 40px)`、字重 700、字距 `-0.02em`；正文 15–16px、行高 1.7。

### 2.5 圆角

圆角保持 8px / 12px 不变。它不是原站独有的签名，改了反而要回归所有页面。

## 6. AGENTS.md 规则调整建议（只写建议，本次不改）

现在的 `AGENTS.md` 还是复刻阶段的规则，和定制阶段冲突的有三条：

| 现有规则 | 问题 | 建议改成 |
|---|---|---|
| Pixel-perfect emulation — match the target 1:1 | 定制阶段的目标恰恰是「不像原站」 | **Design source of truth** — `docs/REDESIGN.md` 的 token 和组件约定是唯一审美依据；不再对照原站截图 |
| No personal aesthetic changes during emulation phase | 已进入定制阶段 | **Customization phase** — 审美改动按 REDESIGN.md 走；新增视觉语言先改方案再改代码 |
| Real content — use actual text and assets from the target site | 会把原站文案和素材继续带进来 | **Own content only** — 文案用本站业务语言（外贸 CRM 客户成功场景）；不新增原站文字、图片、logo；第三方素材要有许可并去掉作者信息 |

建议新增：

1. **Freeze rules** — 页面、分类、导航的冻结和解冻以 `PROJECT.md` §4.1 为准，代码 agent 不自行解冻。
2. **No re-introduction** — 改动不得重新引入 §4「改掉」栏里的签名（克莱因蓝、8 色主题点、网格光晕、Manrope 字标等）。
3. **Attribution check** — 每次提交前 grep 作者信息（署名、公众号、微信号、知识星球、专栏、作者域名）；第三方代码按其 LICENSE 署名，模板 MIT 声明保留。
4. 顶部的 Next.js 版本提示块保留（由 `next dev` 自动写入）；「Website Reverse-Engineer Template」一节改名为「项目来源」，只保留 MIT 来源说明。

改完后按现有规定跑 `bash scripts/sync-agent-rules.sh`。

## 7. L01 试学后的正式改版步骤

前提：Will 试学完 L01，并确认可以评估下一批改动（冻结规则：试学完只代表可以评估）。每周建站 1–2 小时。

| 步 | 内容 | 预计工时 |
|---|---|---|
| 1 | Will 在样稿分支上验收首页和 token；定下 §8 的问题 | 0.5h（Will） |
| 2 | token 定稿，合并方式由 Will 决定；课程页、术语页、练习页逐页回归（1440 / 375） | 1.5h |
| 3 | 页脚字标换成系统字或自有字标，删 Manrope；logo 改色、换悬停动画（需解冻导航） | 1h |
| 4 | 残留清理：§5 第 1–3 项移出仓库（需 Will 批准删除清单）；第 5 项术语示例改写 | 1.5h |
| 5 | 插图替换：§5 第 4 项换成自有示意图 | 1–2h |
| 6 | localStorage 键迁移（读旧键、写新键）、`vh-*` 类名整理 | 1h |
| 7 | AGENTS.md 按 §6 改，跑同步脚本 | 0.5h |
| 8 | `npm run check`、浏览器检查、作者信息 grep、独立复核 | 1h |

合计约 8–9 小时，按每周 1–2 小时大约 **5–8 周**。这是估算（inference），依据是本次样稿实际用时和改动面，第 5 步插图的工作量最不确定。
