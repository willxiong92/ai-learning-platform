## 1. 结论

**这个项目要做的不是一个学习站，而是一个"业务 AI 实践平台"。它先有能直接用在业务上的项目，再用学习去支撑这些项目。**

- **业务项目**：Will 围绕一线真实业务做 AI 项目。一线的真实业务是三件事：服务客户、外贸场景、给客户做 Accio Work（AWB，口头也叫 Hwork）的 AI 赋能。项目做成后，沉淀成一线拿来就能用的模板、Skill、SOP 和案例。
- **团队平台（克隆站）**：新的主管工作台，学和做放在一起。上面有：
  - 业务项目案例库，可以直接参考复用；
  - 课程与术语，用来补做项目需要的知识；
  - 实践作业，产出成果卡素材。
- **个人网站**：对外窗口。从上面两项里挑出 Will 自己的、脱敏后的好东西，发到 GitHub 上和同行交流。

一句话：**项目先行，学习跟随，对外分享收尾。**

## 2. 项目背景

| 背景 | 事实 | 对本项目的含义 |
|---|---|---|
| **脱节问题**（本项目的起因） | 这半年 Will 的重心在个人 AI 学习和个人项目上，比如建站。一线日常用 AI 则都围绕业务：服务客户、外贸场景、给客户做 Accio Work 的 AI 赋能。Will 发现两边脱节，一线觉得这些东西"用不到、不关心、不了解"（Will，9-18） | 平台的首要内容，必须是一线业务里能直接用的东西 |
| 业务定位 | AI 学习与实践是部门的主营业务线，也是正在推进的项目 | 学习不能脱离业务单独做 |
| 产品背景 | Accio Work（AWB）是集团 ICBU 的核心产品，资源向它倾斜（出处：团队沟通纪要 FY27Q1）。Hwork、Accio Work、AWB 是同一个产品（Will 9-18 确认；业务主线写作「Accio Work（AWB）」）。它既是客户在用的产品，也是一线自己的 AI 工具 | Accio Work 赋能要作为第一优先的业务场景 |
| 考核机制 | 北森 5/3/2：<br>• 业务绩效 50%<br>• 非业务产出 30%，由 AI 龙虎榜评审<br>• 团队贡献 20%，由主管评，带教、复制算在这里 | 一线参考 Will 的项目做出成果，就能计分，这是一线的动力来源 |
| 成果卡规则 | 每人每季 1 个主项目、至少 1 张卡。卡上要标 P 阶段、SC 场景、gap_id，类型分知识 / 能力 / 经验。红线：必须有产线客户环境的运行证据，纯 POC 打回 | 平台上的项目要带产线证据；学习作业只能算素材 |
| 龙虎榜节奏 | 8–9 月扫盲，10–11 月打磨，12 月后分化 | 项目和课程的排期按这个节奏走 |
| 业务场景 | 一期边界表：<br>• 成熟：SC-P1-01/02、SC-P2-01、SC-P3-01/02<br>• 线上必收：SC-AWB-01<br>• 龙虎榜必收：SC-OKKI-01<br>• 其余待验证 | 首批业务项目只选成熟或必收的场景 |
| 学习资产 | 4 处资产：<br>• VibeHub 克隆站<br>• 前端小课<br>• 旧工作台学习层<br>• AI学习站 `sources/` | 全部收进克隆站；旧工作台弃用，里面有用的资产按清单迁过来 |

## 3. 需求

### 3.1 三类用户

| 用户 | 要什么 | 衡量方式 |
|---|---|---|
| 一线 CSM、交付（主要用户） | 拿到能直接用在客户身上的 AI 做法，包括 Accio Work 赋能、外贸场景的模板和 Skill；会用、会核验；能做成成果卡 | 参考平台项目做出至少 1 张成果卡草稿；实际复用次数 |
| 主管 | 批阅作业、组织带教，把个人实践变成团队实践 | 批阅记录；有复制案例 |
| Will | 做出一线用得上的业务项目；个人 FDE 成长；对外分享 | 项目被一线复用；24 章学习证据；个人网站发布 |

### 3.2 功能需求

**团队平台（克隆站）**

1. **业务项目案例库（新增，排第一）**。每个项目一页，包括：
   - 解决哪个业务问题，挂哪个 SC 场景和 gap；
   - 怎么用，要有一线可以照做的步骤；
   - 可复用资产，比如 Prompt、Skill、SOP、模板；
   - 产线证据；
   - 边界：能做 / 待验证 / 不支持；
   - 关联的课程章节。
2. **课程与术语**：10 个领域、24 章。每章有：
   - 目标、正文、示范、练习、测验；
   - 一张实践作业卡，指向案例库里的项目。
3. **学习路线**：团队 = 必修包 + 本季主项目对应的项目和章节；个人 = 24 章。
4. **做**：实践作业卡和成果卡草稿。首期不上后端：草稿存本机，一键复制后走现有流程提交（第 10 节 Q2）。
5. **我的学习**：阅读、测验、收藏。

**个人网站（对外）**

6. 发布 Will 原创的方法、总结和项目复盘，托管在 GitHub。

### 3.3 约束

- **团队平台只在内部使用。** VibeHub 授权限内部学习、不商用；前端小课是付费内容，限内网。
- **个人网站只放 Will 的原创内容，并且要脱敏。** 以下内容一律不上个人网站：
  - VibeHub 内容
  - 前端小课正文
  - 客户材料
  - 公司内部数据
  - 员工考核信息
  - 未公开的产品规划
- 任何地方都不放客户原始数据。示例一律标"模拟"。
- **母源唯一**：
  - 术语和平台内容在克隆站；
  - 24 章正文在学习站 `sources/`；
  - 业务事实在业务主线。

### 3.4 明确不做

- 英文版、语言切换、交流群。
- 旧工作台不再迭代。
- 首期不做团队成绩统计。

## 4. 方案框架

三条线、一个闭环：

```
                 ┌───────────── 业务主线（母源）─────────────┐
                 │ 边界表 · 缺口清单 · 本体论 · 六包 · 成果卡规则 │
                 │ AI场景知识库 · 北森/龙虎榜规则               │
                 └──────────────────┬───────────────────────┘
                                    │ 选题（成熟 / 必收场景）
                                    ▼
 ┌─ 线① 业务 AI 项目（Will 先做）──────────────────────────────┐
 │ 服务客户 · 外贸场景 · Accio Work (AWB) 赋能                        │
 │ 在产线跑通 → 沉淀：Prompt / Skill / SOP / 模板 + 产线证据     │
 └──────────────────┬──────────────────────────────┬──────────┘
                    │ 上架                          │ 挑选 · 脱敏 · 原创
                    ▼                               ▼
 ┌─ 线② 团队平台（克隆站 = 新主管工作台）────┐  ┌─ 线③ 个人网站 ─────┐
 │ 案例库：拿来就用                           │  │ 方法 · 复盘 · 总结  │
 │ 课程/术语：补做项目需要的知识（10 领域）   │  │ GitHub · 同行交流   │
 │ 作业卡：照着项目在自己客户上做一次         │  │ （对外）            │
 │ 成果卡草稿 → 主管批阅 → 龙虎榜             │  └────────────────────┘
 └──────────────────┬───────────────────────┘
                    │ 一线的好实践回流（带教 · 复制 · 新案例）
                    └──────────────► 回到线①，成为新项目 / 新案例
```

### 4.1 闭环

| 环节 | 谁 | 做什么 | 产出 | 计入什么 |
|---|---|---|---|---|
| 1 做项目 | Will | 选成熟场景，在产线跑通 | 项目和可复用资产，附产线证据 | Will 自己的成果卡 |
| 2 上架 | Will | 整理成案例页，挂课程章节 | 平台案例 | — |
| 3 学 + 用 | 一线 | 按需补课，照着案例在自己的客户上做一次 | 作业、成果卡草稿 | 北森 30% |
| 4 批阅 | 主管 | 批阅，挑出好实践 | 批阅记录 | 主管团队贡献 |
| 5 回流 | 一线 / 主管 | 好实践变成新案例；带教同事 | 新案例 | 北森 20% |
| 6 外发 | Will | 挑原创内容脱敏后发布 | 个人网站文章、GitHub 仓库 | 个人影响力 |

### 4.2 学习层怎么服务项目

- 10 个领域的分类不变。一线必修 A、B、G、H、I，外加 Accio Work。Accio Work 同时是一线的工具和客户赋能的对象，所以 J 领域的 Accio Work 实操和 H 领域的客户赋能场景要连起来教。
- 课程的顺序从"按知识体系排"改为"**按项目需要排**"：每个案例页列出"做这个项目要先懂的 3–5 个知识点"，一线按需点进去学。
- 24 章完整路线保留给 Will 的个人 FDE 路线，也给想深学的同事。
- 各模块与业务的对应，沿用 v1 第 4.2 节的初步推断，S3 阶段再逐章核对：M1 对应 Accio Work 边界与证据；M2 对应 SC-P1-01 质检；M4 对应 SOP 和 OKKI 字段映射；依此类推。
