在这篇指南里，我想延续面向大众的大语言模型（LLM）科普系列。在上一期视频 [《深入理解大语言模型（Deep Dive into LLMs）》](https://book.oiloil.org/articles/deep-dive-into-llms) 中，我们拆解了这些模型在底层是如何训练出来的，以及应该如何理解它们的认知方式与“心理学”；而这一次，我想完全聚焦在 **日常实战应用** 上——带你走遍目前主流工具里的各项功能与设置，通过大量我亲身使用的一手案例，向你展示我是如何把大语言模型融入日常工作与生活的。

我们先来看一眼当下的大模型应用生态。2022 年底，OpenAI 推出了 ChatGPT，人类历史上第一次可以让普通人通过一个简单的文本输入框直接与大语言模型对话，瞬间席卷了整个互联网。

到了今天，围绕大语言模型的应用生态已经变得无比丰富。因为 ChatGPT 诞生最早、用户最多、功能集成度也最高，我在下文中会用它演示很多基础操作；但现在的格局早已不是一家独大，不管是科技巨头还是初创公司，都推出了各具特色的同类产品，甚至在不少细分体验上超越了 ChatGPT：

- **科技巨头阵营** ：Google 推出了 Gemini，Meta 有 Meta AI，微软则有 Copilot；
- **前沿初创公司** ：Anthropic 打造了 Claude，马斯克创立的 xAI 推出了 Grok，中国团队推出了 DeepSeek，法国团队 Mistral 则有 Le Chat。

面对这么多模型，平时怎么知道哪家最强？除了自己上手试，我通常会参考两个公开榜单：一个是 [Chatbot Arena（LMSYS）](https://lmarena.ai/) ，它通过让真实用户对两个匿名模型的回答进行盲测投票，计算出类似国际象棋的 Elo 积分排名；另一个是 Scale AI 维护的 [SEAL Leaderboard](https://scale.com/leaderboard) ，可以查看各家模型在不同专业评测维度上的最新得分。

## 1\. 聊天的底层本质：一维 Token 序列与「1 TB 压缩包」心智模型

当我们打开 ChatGPT，面对屏幕中央那个写着 *“What can I help with?”* 的输入框时，里面到底发生了什么？

最基础的交互方式是：我们输入一段文字，模型回给我们一段文字。比如大语言模型天生非常擅长写作——无论是写俳句（Haiku）、诗歌、求职信、简历还是回复邮件。我们可以先让它写一首关于「作为大语言模型是什么感受」的俳句，它会很快给出回复：

> *Words flow like a stream,*（文字如溪流淌，） *Endless echoes, never mine,*（无尽回响，皆非我属，） *Ghost of thought unseen.*（无形思想的幽灵。）

在网页界面上，这看起来就像你和朋友在微信里你一言我一语地发聊天气泡。但在底层，模型看到的并不是“句子”或“气泡”，而是被切碎成一个个小文本块的 **一维 Token 序列** （在英文里，1 个 Token 大约对应四分之三个单词或几个常见字母组合；中文里则往往对应半个到一个汉字）。

我们可以打开 [Tiktokenizer](https://tiktokenizer.vercel.app/) 网站，在左上角选择 `gpt-4o` 的分词器（Tokenizer），把刚才那句提问贴进去：网页会用不同颜色的色块标出切分结果——我输入的英文句子被精确切成了 **15 个 Token** ，模型的俳句回复则对应 **19 个 Token** （ `gpt-4o` 的总词表里一共收录了约 `200,000` 种这样的基础 Token 片段，且严格区分大小写与空格）。再算上底层对话格式（Chat Format）里用来标记「用户消息开始」「用户消息结束」「助手消息开始」的特殊控制 Token，刚才那两个简单的聊天气泡，在底层其实是一串严丝合缝、总计 **42 个 Token** 的一维序列。

每次跟大模型对话时，我脑子里浮现的底层运行图景是这样的：

1. **共建上下文窗口（Context Window）** ：当你点击左上角的 **New Chat（新对话）** 时，系统会开启一条空白的一维 Token 序列。你打字并按下回车，相当于往序列里写入了一串用户 Token，并把控制权移交给语言模型；模型顺着序列往后续写它的回复 Token，直到吐出一个代表「我说完了」的特殊停止 Token，应用程序再把控制权交还给你。你和模型轮流往里续写的这条完整 Token 流，就叫做 **上下文窗口** ——它相当于当前对话的 **短期工作记忆（Working Memory）** ，只有装在这个窗口里的内容，模型才能直接读到。而点击 **New Chat** ，本质上就是把整个上下文窗口彻底清空归零。
2. **预训练（Pre-training）造出「1 TB 的有损压缩包」** ：我们对话的这个模型实体，训练过程分为两大阶段。第一阶段是 **预训练** ：把整个互联网网页抓取下来切成 Token，让一个包含约 1 万亿参数（Parameters）的神经网络不断练习「预测下一个 Token」。这个过程就像把整个互联网打包压缩进了一个大约 **1 TB 大小的 `.zip` 压缩包** 里。但要注意，1 TB 根本不可能一字不差地装下整个互联网，所以它是一个 **有损的、概率性的压缩包** ——模型记住的是互联网知识的整体印象与统计规律。而且预训练极其昂贵（动辄耗资数千万美元、在庞大的 GPU 集群上训练好几个月），不可能每天重跑，因此模型自带的知识总是滞后的，存在一个明确的 **知识截止日期（Knowledge Cutoff）** 。
3. **后训练（Post-training）给压缩包贴上「助手笑脸」** ：只会续写互联网网页的预训练模型还不能直接拿来聊天。所以在第二阶段 **后训练（早期主要指监督微调 SFT）** 中，工程师会把训练数据替换成由人类标注员（Human Labelers）精心编写的问答对话数据集，教模型学会以“乐于助人的 AI 助手”的语气和格式来回答问题。
![一维 Token 序列与「1 TB 压缩包」心智模型](https://book.oiloil.org/assets/articles/how-i-use-llms/01-token-stream-and-zip-model.svg)

一维 Token 序列与「1 TB 压缩包」心智模型

如果让我替 ChatGPT 写一段最诚实的自我介绍，它应该这样对你说：

> **「嗨，我是 ChatGPT，一个保存在硬盘上的 1 TB 压缩包。我的知识来自大约半年前通读过的整个互联网，不过我只记得个大概；而在互联网上被反复提及的高频常识，我会比冷门罕见的细节记得清楚得多（这一点跟人类很像）。至于我讨喜的说话风格，则是 OpenAI 的人类标注员通过示范案例写进我脑子里的。」**

理解了这个「1 TB 压缩包」心智模型，你就抓住了最重要的一条认知底线： **在默认状态下，你对话的只是一个完全封闭、孤立的静态文件** ——它里面既没有计算器、没有 Python 解释器，也没有连接实时互联网的浏览器；你给它一串 Token，它就凭着半年前对互联网的模糊记忆给你回一串 Token。

## 2\. 仅靠模型自身记忆提问的边界，以及两条核心日常习惯

既然不借助外部工具时，我们只是在跟一个「存着半年前互联网模糊记忆的 1 TB 压缩包」聊天，那什么样的日常问题可以放心直接问它？

我的判断标准是同时满足三个条件： **① 不涉及最近刚发生的动态信息** ； **② 属于互联网上随处可见的高频常识** ； **③ 容错率高（不是高风险场景），或者你自己能顺手核验结果** 。

举两个我这周刚用过的生活实例：

- **查美式咖啡的咖啡因含量** ：今天早上我想对比美式咖啡（Americano）和抹茶的提神效果，就问 ChatGPT：「一杯单份浓缩（one shot）的美式咖啡里大约有多少咖啡因？」它直接回答「大约 `63 毫克` 」。之所以敢直接问，是因为咖啡因含量既不是昨天才变的新闻，也是网上被讨论过成千上万次的高频常识，模型的“压缩包”里肯定记得很牢。我事后顺手去查了一手资料核对，确实就是 63 毫克左右。
- **感冒流鼻涕该吃家里哪盒药** ：前两天我有点感冒流鼻涕，想看看家里备着的 DayQuil（日间感冒药）和 NyQuil（夜间感冒药）哪个对症。ChatGPT 帮我梳理了两款药的有效成分，指出缓解流鼻涕需要靠 NyQuil 里的抗组胺成分（Doxylamine succinate），还解答了吃下去大概多久起效、里面的对乙酰氨基酚（Acetaminophen）是不是就等同于泰诺（Tylenol）。注意： **因为模型本质上只是在输出概率记忆，我绝对不会盲目听信它列的药品成分** ——我当场把家里的 NyQuil 药盒拿出来，对着背面成分表逐一核对，确认它一个字都没记错后才服下，鼻塞流涕很快得到了缓解。

在日常高频对话中，我还有 **两条强烈建议大家养成的基础习惯** ：

### 习惯一：一旦切换话题，立刻点「New Chat」开启新对话

很多人在用一个聊天窗口时，喜欢把毫不相干的问题全往同一个会话里塞，聊出几百屏长。 **只要你准备换一个新话题，前面聊过的 Token 对接下来的问题不再有参考价值，请立刻点击左上角的「New Chat」把上下文窗口清空。**

原因在于，留在上下文窗口里的历史 Token 是很“贵”的，这种昂贵体现在两方面：

1. **分散注意力，拉低回答质量** ：上下文窗口是模型的工作记忆。如果里面塞满了上一段话题留下的几千个无关 Token，模型在预测新问题的回答时很容易被旧信息干扰，导致准确率下降。
2. **拖慢生成速度，增加计算成本** ：底层神经网络每往下生成 1 个新 Token，都要把当前窗口里已有的所有 Token 重新纳入注意力计算。窗口越臃肿，生成下一个词的速度就越慢、消耗的算力也越多。把上下文窗口当成宝贵的稀缺资源，保持它干净精简，模型会跑得既快又准。

### 习惯二：时刻看清左上角的模型档位，组建自己的「LLM 智囊团」

不同等级的模型在智商、文笔和幻觉率上天差地别，千万不要稀里糊涂地用着缩水小模型却抱怨 AI 不好用：

- **警惕未登录或免费档的默认降级** ：如果你在浏览器隐身窗口（未登录状态）下打开 `chatgpt.com` ，或者只用免费档（Free Tier），后台默认分配给你的往往是小号模型 `GPT-4o mini` ——它的参数量小得多，不仅知识储备少、写东西缺乏灵气，也更容易一本正经地胡说八道。
- **看懂主流订阅分档** ：以 ChatGPT 为例，免费档主打 `GPT-4o mini` ；开通 `$20/月` 的 **Plus** 会员，才能稳定用上真正的旗舰大模型 `GPT-4o` （细则里限制为每 3 小时最多 80 条消息）；而开通 `$200/月` 的 **Pro** 会员，则可以无限量使用 `GPT-4o` ，并解锁最顶配的思考模型 `o1 pro mode` 与 `Deep Research（深度研究）` 。其他厂商也是同理：在 Claude 里开通 Pro 才能高频使用主力 `Claude 3.5 / 3.7 Sonnet` （免费档很容易退回小模型 Haiku）；用 Grok 时也要确认自己选中的是最新发布的 `Grok 3` 而不是上一代的 `Grok 2` 。
- **组建你自己的「LLM 智囊团（LLM Council）」** ：因为我每天的专业工作都要写大量代码、查大量资料，哪怕是每月 200 美元的顶配订阅对我来说性价比依然极高，所以我干脆同时付费订阅了多家服务（ChatGPT、Claude、Gemini、Grok、Perplexity）。每当遇到开放性决策或拿不准的问题——比如前阵子计划跨年度假去哪座城市玩，我就把同一个问题同时发给了 Claude 和 Gemini，结果它俩不约而同地强烈推荐瑞士的采尔马特（Zermatt）；我听从了这套“大模型智囊团”的联合建议去了采尔马特，体验确实棒极了。

## 3\. 思考模型（Thinking Models）：用强化学习解锁「内部独白」

聊完了基础对话，我们来看过去一两年整个大模型领域最重要的一项突破： **思考模型（Thinking Models，也常被称为推理模型 Reasoning Models）** 。

在前面提到的预训练（获取互联网知识）和监督微调（跟着人类示范学会助手对话格式）之后，现在的顶级大模型在后训练阶段普遍引入了更关键的第三步—— **强化学习（Reinforcement Learning，简称 RL）** 。DeepSeek 团队公开发表的 `DeepSeek-R1` 论文（ *Incentivizing Reasoning Capabilities in LLMs via Reinforcement Learning* ）非常清晰地展示了这一过程。

在强化学习阶段，工程师不再靠人工手写标准思考步骤去喂给模型（因为面对复杂难题，人类标注员自己也很难写出完美的思维模版），而是直接给模型成千上万道有客观评判标准的数学题与编程题，让模型自己反复试错练习。在追求高解题正确率的过程中，模型自己涌现出了一套极为接近人类解难题时的 **内部独白（Inner Monologue）策略** ：它会先提出几种假设、顺着推演几步，发现走不通就立刻自我怀疑并回溯（ *“Wait, that doesn't look right... let's check the order...”* ），换条路径重新验证，直到推导通顺后再给出最终答案。

回到我们的心智模型图，这意味着那个「贴着笑脸的 1 TB 压缩包」头顶上，多出了一个可选的 **思考气泡（Thinking Bubble）** 。当你切到思考模型时，模型在正式回答前会先花几十秒甚至好几分钟，在思考气泡里吐出成千上万个推理 Token。

### 实战案例：一行让 GPT-4o 束手无策的梯度检查（Gradient Check）Bug

为什么有些时候必须等这几分钟？看一个我前几天写代码时真实卡住的例子。

当时我在手写一个基础神经网络（多层感知机 MLP）的优化器，在跑 **梯度检查（Gradient Check）** 时发现数值梯度和解析梯度死活对不上，但我自己盯着代码看了半天也没找出 Bug 在哪。

1. **先问非思考模型 `GPT-4o`** ：我把整段代码复制粘贴给 OpenAI 的旗舰对话模型 `GPT-4o` 。它秒回了一大串常见的调试建议（检查激活函数导数、检查学习率等），听起来头头是道，但 **没有一条命中真正的 Bug** ，问题依然没解决。
2. **切换到思考模型 `o1 pro mode`** ：在 OpenAI 的模型下拉菜单里，所有以字母 `o` 开头的型号（如 `o1` 、 `o3-mini` 、 `o3-mini-high` 以及 `$200/月` Pro 专属的 `o1 pro mode` ）全都是经过强化学习训练的思考模型。我把 **一模一样的提示词和代码** 发给 `o1 pro mode` ——它在后台思考了整整 1 分钟，然后直接一针见血地指出了病根： **我在把权重与偏置参数打包（pack）成一维向量、以及在反向传播里解包（unpack）累加梯度时，两边的排列顺序写反了（就好比搬家装箱时按「先装书、后装衣服」的顺序打进箱子，拆箱清点时却按「先算衣服、后算书」的顺序去对账）！** 我照着改完一行代码，Bug 当场解决。
3. **横向测试「智囊团」其他模型** ：为了验证各家水平，我把同一段 Bug 代码挨个发给了其他平台：
	- `Claude 3.5 Sonnet` （甚至在还没开思考模式的情况下）、 `Gemini` 和 `Grok 3` 全都准确抓出了这个参数打包顺序不匹配的 Bug；
		- 我还在 [Perplexity](https://www.perplexity.ai/) 的模型选择框里切到了它托管的 **`DeepSeek-R1`** 。最酷的是，你可以点开 DeepSeek-R1 的原始思考过程（Raw Thoughts），亲眼看到它的“脑内独白”：它先顺着读代码，读到一半突然停住说\*「等等（But wait），他们在累加梯度时的方式不对，让我们检查一下参数打包的顺序……哇，这是一个致命错误（That's a critical mistake）！」\* 经过几分钟推演后，同样给出了满分修复方案。

**我的思考模型使用准则** ：思考模型主要在 **高难度数学推导、复杂代码调试和严密逻辑推理** 上带来巨大的准确率提升；如果你只是想问问去哪旅游、润色一封邮件，千万别开思考模型白等一分钟。我日常总是 **默认先用响应飞快的普通模型；一旦发现它答在表面、没解决核心问题，再立刻切到思考模式（如 OpenAI 的 `o` 系列、Claude 3.7 刚上线的 `Extended Thinking` 、Grok 输入框左下角的 `Think` 按钮或 `DeepSeek-R1` ）让它深入推演** 。

## 4\. 工具调用（一）：联网搜索（Internet Search）与深度研究（Deep Research）

到目前为止，我们讨论的都还局限于模型自身的神经网络参数。但就像前面说的，那个「1 TB 压缩包」是封闭且滞后的。为了让模型突破知识截止期的限制，我们需要给它装上外部工具（Tool Use）——其中最基础、最常用的第一个工具就是 **联网搜索（Internet Search）** 。

![从封闭压缩包到外部工具调用：思考气泡、联网搜索、文档上传与代码沙盒如何协同更新上下文窗口](https://book.oiloil.org/assets/articles/how-i-use-llms/02-tools-and-context-loop.svg)

从封闭压缩包到外部工具调用：思考气泡、联网搜索、文档上传与代码沙盒如何协同更新上下文窗口

### 联网搜索的底层原理与日常场景

几天前我在追美剧《白莲花度假村》第三季（ *The White Lotus Season 3* ），看完第一集觉得太精彩了，想知道第二集具体哪天播出。

由于这部剧是最近刚开播的，半年前预训练好的「1 TB 压缩包」里绝对不可能有它的排期表。放在过去，你得打开 Google 输入关键词，在搜索结果里点开四五个充满烦人弹窗广告和SEO凑字数废话的娱乐网页，自己肉眼翻找播出时间表。

而给大模型装上联网搜索工具后，底层的运行流程变成了这样：

1. 模型读到你的问题，意识到这是近期信息，于是吐出一个特殊的 **「调用互联网搜索」Token** 并暂停续写；
2. 外部应用程序（如 Perplexity 或 ChatGPT）接管控制权，拿着模型生成的搜索词去搜索引擎检索，自动打开排名前十的网页，把这些网页里的正文提取出来（可能有好几千个 Token）， **直接复制粘贴进当前的上下文窗口（工作记忆）里** ；
3. 模型重新接管控制权，此时那些新鲜网页的全文已经摆在它的短期工作记忆里了，它只需要阅读这些材料，就能立刻给你总结出干净准确的各集播出时间表，并在句末附上引用网页链接（Citations）供你随时点进去核实。

我日常遇到以下两类问题时，会本能地直接使用联网搜索（出于习惯我经常直接打开最早把搜索体验做顺的 **[Perplexity](https://www.perplexity.ai/)** ，当然现在 ChatGPT 点亮 `Search` 按钮或用 Grok 也一样好用）：

- **第一类：随时会发生变化的新鲜动态信息** 。例如：「今天美股开盘吗？（刚好赶上美国总统日假期）」「《白莲花度假村》第三季是在哪里取景拍摄的？」「Vercel 现在官方提供托管的 PostgreSQL 数据库吗？（科技公司的产品线每个月都在变，不能信旧记忆）」「明天苹果发布会有什么靠谱的爆料？」「《单身即地狱》第四季的嘉宾阵容有哪些人？」「《文明 7（Civilization VII）》具体哪天解锁？」「Palantir 最近的股价为什么一直暴涨？」「现在去越南旅游安全吗？」或者当我在 X（Twitter）时间线上看到大家突然都在刷某个缩写词（比如前阵子的 `USAID` ），单条推文没头没尾看不懂背景时，我就会直接扔给搜索工具说\*「告诉我最近关于 ×× 到底发生了什么，核心来龙去脉是什么」\*。
- **第二类：互联网上讨论极少的小众冷门细节** 。哪怕某件事不是昨天刚发生的，但如果它太冷门、在网上出现的次数太少，模型在预训练压缩时也很可能没记住。比如我好奇抗衰狂人 Bryan Johnson 平时刷牙用什么牌子的牙膏，这种既冷门又可能随时间更换的细节，直接用联网搜索一查一个准。

需要注意的一点是： **不同平台、甚至同一平台的不同模型型号，对联网搜索的支持程度并不统一** 。有时模型会自动判断需要联网，有时则得由你手动点亮输入框里的 `Search` 按钮（我用 `GPT-4o` 查近期信息时，为了保险都会手动点亮 `Search` ）。而在拍摄这期视频时，Claude 还没有内置联网搜索功能，问它《白莲花度假村》第三季排期，它会老老实实回答「我的知识截止于 2024 年 4 月，无法提供后续播出日期」；Gemini 里 `2.0 Flash` 可以联网搜索并给出引用源，但当时最强的 `2.0 Pro Experimental` 却提示不支持实时联网信息。因此，清楚知道自己手头的模型有没有挂上搜索工具非常重要。

### 深度研究（Deep Research）：联网搜索 × 思考模型的长周期闭环

如果把前面的 **「联网搜索」** 和 **「思考模型」** 结合起来，再允许模型在后台连续跑上十几二十分钟，会发生什么？这就诞生了最近刚上线、但我认为极其惊艳的一项新能力： **深度研究（Deep Research）** 。

目前这项功能包含在 ChatGPT 的 `$200/月` Pro 订阅中（Perplexity 随后也跟进了同名的 `Deep Research` 选项，Grok 3 则推出了类似的 `DeepSearch` ）。当你开启 Deep Research 提交一个复杂课题时，模型通常会先向你反问两三个澄清问题（确认研究侧重点与文献范围），接着便在后台展开长达 5 到 20 分钟的「思考 → 发起多轮搜索 → 阅读几十篇论文与网页 → 发现新线索再继续搜索思考」的深度循环，最后为你交付一篇结构完整、处处标明文献出处的定制研究报告。

分享几个我最近用 Deep Research 解决的实际问题：

1. **深挖长寿补剂成分 Ca-AKG 的真实科学依据** ：前阵子我在网上看 Bryan Johnson 的「蓝图计划（Blueprint）」补剂包，里面有一款叫 *Longevity Mix* 的冲剂，每勺含有 `2.5 克` 的 **Ca-AKG（α-酮戊二酸钙）** ，商品页只含糊写着“促进能量生成、维持活力”。我想搞清楚这玩意儿到底是不是智商税，于是打开 Deep Research 输入提示词： *「Ca-AKG 是 Bryan Johnson 长寿冲剂里的核心成分（每份 2.5g）。请帮我深入调研 Ca-AKG：为什么它会出现在抗衰配方里？它在动物模型或人体临床试验中的真实有效性如何？潜在的作用机制是什么？有没有任何安全性隐患或毒副作用？」* 回答完它的澄清问题（兼顾人体临床与动物模型）后，ChatGPT 思考并检索了 5 分钟、仔细阅读了 **27 篇科学文献** ，给我写出了一份堪比专业文献综述的报告——详细拆解了它在三羧酸循环（Krebs cycle，人体细胞把营养转化为能量的核心代谢环路）中的角色、在线虫/果蝇/小鼠实验中的延寿数据、目前有限的人体表观遗传时钟试验（通过检测 DNA 甲基化程度来评估生理年龄），以及高剂量可能引起的肠胃不适。
2. **对比 Brave 与 Arc 浏览器的隐私保护机制** ：因为 Chrome 浏览器有一次崩溃把我的所有标签页全弄丢了，我决定换一款主力浏览器，在 Brave 和 Arc 之间纠结谁的隐私安全性更好。我让 Deep Research 写了一份深度对比报告，顺着它给出的技术来源看下来，结论非常明确：Brave 在默认隐私拦截和数据隔离上明显胜出——这也是为什么你现在看到我录屏用的是 Brave 浏览器。
3. **调研小鼠寿命延长实验技术** ，以及 **整理全美主流大模型实验室（LLM Labs）的规模与融资对比表** 。

横向对比下来，目前 **ChatGPT Pro 的 Deep Research 报告质量是断档领先的** ——篇幅最详实、逻辑最严密、读起来最通顺；Perplexity 和 Grok 的版本相对简短一些，深度还差一口气。

但在这里我必须强调一条铁律： **永远只把 Deep Research 生成的报告当成你的「研究初稿（First Draft）」和「文献导航索引」，绝不能把里面的每一句话当成绝对真理。**

就拿刚才第三个例子来说：我让它整理「美国本土主流大模型实验室的规模与融资表」，结果生成的表格 **漏掉了马斯克的 xAI** （这显然是一个巨大的遗漏），反而把严格意义上不算基础模型实验室的开源社区平台 Hugging Face 和非营利组织 EleutherAI 塞了进来，表里的部分融资估值数字也经不起细究。即便有联网搜索加持，模型在综合几十篇资料时依然可能漏看、误读甚至产生幻觉。正确的用法是：利用它帮你省掉前 80% 漫无目的找资料的苦力活，然后顺着报告里的引用链接（Citations）点进原始论文去核对关键结论。

## 5\. 工具调用（二）：上传文档与「绝不独自读书」的工作流

理解了联网搜索之后，你会发现它的本质其实就是： **不再让模型单靠脑子里模糊的预训练参数去猜，而是把具体的参考文档直接塞进模型的上下文窗口（工作记忆）里，让它看着原文回答问题。**

除了让模型去网上搜网页，我们还可以主动通过 **文件上传（File Upload）** ，把电脑上的 PDF 论文、技术文档或整本书的章节直接放进它的上下文窗口里。

![「绝不独自读书」伴读工作流：以伴读 1776 年《国富论》为例](https://book.oiloil.org/assets/articles/how-i-use-llms/05-co-reading-wealth-of-nations.svg)

「绝不独自读书」伴读工作流：以伴读 1776 年《国富论》为例

### 案例一：跨界阅读前沿生物学论文（Arc Institute 的《Evo 2》）

几天前，生物研究机构 Arc Institute 发布了一篇重磅论文《Evo 2》，用训练大语言模型的方法在海量物种的 DNA 基因组序列上训练了一个生物学基础模型。我不是生物学出身，平时自己硬啃这种跨领域的顶刊论文会非常吃力；但现在，我只需要把这份 30MB 的 PDF 论文直接拖进聊天框里。

在底层，应用通常会把 PDF 里的正文提取转换成纯文本 Token 流，装载进上下文窗口。不过要注意，不同平台对超长文档的承载力不同——比如当时我把这份 30MB 的 PDF 直接拖给刚发布的 Claude 3.7 时，系统提示超出了单次会话长度限制，换成 ChatGPT 的 `GPT-4o` 则顺利读入；另外，目前大多数系统在解析巨型 PDF 时主要提取文字，可能会丢弃插图，对复杂科研图表的理解也还不如人类深入。

一旦论文装进了上下文窗口，我总是先说一句： **「请先帮我概括一下这篇论文的核心内容。」** 读完它生成的结构化摘要、建立起全局框架后，我再开始从头读论文的引言和正文，每读几段遇到不懂的生物学术语或实验设计，就随时在聊天框里追问。

### 案例二：让大模型陪读 1776 年的《国富论》——「不要再自己一个人闷头读书了」

我现在养成了一个雷打不动的习惯： **我几乎再也不会自己一个人孤零零地读一本书了，只要读书，旁边一定开着一个大模型陪我一起读。**

比如我最近在读亚当·斯密（Adam Smith）写于 1776 年的经济学开山之作《国富论》（ *The Wealth of Nations* ）。这本书虽然写于两百多年前，但里面的洞察放在今天依然极为犀利。不过，因为它是 18 世纪的古典英文著作，句式长、用词古雅，如果自己一个人硬啃，很容易读着读着就走神或者卡在某个长难句上。

虽然 Claude 和 ChatGPT 在预训练时肯定都读过《国富论》，但如果你不给原文、直接空口问它「第一卷第三章讲了什么细节」，它脑子里的记忆是模糊的。因此，我现在读书的标准流程是这样的：

1. **找到书籍的纯文本原文** ：像《国富论》这种公版书，可以直接在 [Project Gutenberg（古腾堡计划）](https://www.gutenberg.org/) 上免费打开全文网页；
2. **把当前要读的这一章贴进上下文窗口** ：比如我正准备读第一卷第三章《论分工受市场范围的限制》（ *That the Division of Labour is Limited by the Extent of the Market* ）。我直接把这一整章的原文复制粘贴进 Claude 的输入框（文本较长时 Claude 会自动把它折叠成一个清爽的 `PASTED` 文本附件卡片），先让它给我写一段本章导读摘要；
3. **一边读原文，一边随时追问讨论** ：心中有数之后，我开始逐段精读原文。遇到任何拗口的 18 世纪古英语表达、拿不准的历史背景，或者我想跟它探讨某个经济学推论时，切回聊天框直接问它。

我发现，用这种「左手原文、右手大模型」的方式读书， **不仅让跨学科书籍（如生物学）和古典艰深著作（如 1776 年的《国富论》或莎士比亚戏剧）变得平易近人，更让我读完每一章后的理解深度与长期记忆留存率提升了好几倍** 。唯一的遗憾是目前我还得在电子书网页和聊天窗口之间手动来回复制粘贴，显得有点笨拙——我非常期待未来所有的阅读器都能原生内置这种上下文伴读体验。在此之前，强烈建议你也试试： **千万别再自己一个人干巴巴地闷头读书了！**

## 6\. 工具调用（三）：Python 解释器、高级数据分析、Claude Artifacts 与 Vibe Coding

除了查网页和读文档，我们还能给大模型配上一件威力无穷的武器： **代码执行环境（Python 解释器与浏览器沙盒）** 。

![代码执行与沙盒四件套：从拒绝心算、数据分析核验到 Claude Artifacts 与 Vibe Coding](https://book.oiloil.org/assets/articles/how-i-use-llms/06-code-interpreter-artifacts-vibe-coding.svg)

代码执行与沙盒四件套：从拒绝心算、数据分析核验到 Claude Artifacts 与 Vibe Coding

### Python 解释器：别让大模型在脑子里「心算」复杂运算

如果你问 ChatGPT `30 × 9 等于多少` ，它不需要借助任何工具，直接凭着预训练参数里的记忆预测下一个 Token，就能脱口而出 `270` ——就像我们人类背九九乘法表心算一样。

可如果我问它： `3049823 × 23948234982 等于多少？`

换成任何一个人类，看一眼就会立刻放弃心算去找计算器。经过后训练调教的 ChatGPT 也是一样：它非常清楚这种位数的大数乘法靠神经网络直接预测 Token 肯定会算错，于是它会吐出特殊控制 Token 唤起内置的 **Python 解释器（Python Interpreter）** ，写下一行简单的 Python 乘法代码交给沙盒运行，等拿到沙盒返回的精确数字后，再把结果整理成自然语言回答你。

这里有一个 **新手极易踩坑的隐患：不同平台挂载的代码工具不同，一旦某个模型没有挂载代码解释器（或者懒得调用），它就会硬着头皮在脑子里“心算”，并给你编造一个看起来极其逼真的错误答案！**

我在视频里当场测试了这道大数乘法在各家模型里的表现：

- **ChatGPT（ `GPT-4o` ）** ：自动调起 Python 解释器，结果 **100% 准确** ；
- **Claude（ `3.5 / 3.7 Sonnet` ）** ：在分析环境里自动写了一段 JavaScript 代码执行，结果 **100% 准确** ；
- **Grok 3** ：当时没有接入 Python 解释器，于是它直接在脑子里硬算——算出来的长串数字前半截和总位数全都对得上，只有最后几位把正确的 `...1120` 算成了 `...060` ！如果你不拿计算器核对，肉眼扫过去 99% 会被它糊弄过去；
- **Gemini 2.0 Pro Experimental** ：同样没有显示调用任何工具，第一道题居然凭心算蒙对了；但我紧接着把数字再加长几位考它，它立刻败下阵来，心算出了一个开头很像但尾数全错的幻觉数字。

所以，只要涉及严谨的数学计算或数据统计，务必确认模型右上角或步骤条里 **真正调起了代码解释器（写出并运行了代码）** ，绝不要相信大模型的“心算”。

### 高级数据分析（Advanced Data Analysis）：像带一位「手脚麻利但偶尔走神的初级分析师」

在 ChatGPT 里，Python 解释器更强大的应用场景叫做 **高级数据分析（Advanced Data Analysis）** ——你可以上传 Excel/CSV 表格，或者让它先联网搜集数据，再自动编写 Python 代码（调用 `matplotlib` 、 `pandas` 、 `scipy` 等库）帮你做回归分析、画统计图表。

这相当于给你配了一位随叫随到的初级数据分析师。但这位初级分析师有时候会 **自作主张甚至睁眼说瞎话** ，我用一个现场演示的真实翻车案例给你提个醒：

1. **第一步：联网搜集数据** ：我让 ChatGPT 明确使用搜索工具，查出 OpenAI 从 2015 年成立至今历年的公司估值，整理成一张表格。表里 2015 年刚创立时没有公开估值，它标为 `N/A（不适用）` 。
2. **第二步：画对数坐标图（Log Scale）——抓到第一个隐蔽小动作** ：因为 OpenAI 的估值从早期的几亿美元一路暴涨到上千亿美元、跨度相差上千倍，画在普通坐标轴上早期数据全会贴在底边看不清；所以我让它画成 Y 轴按 10 倍阶梯递增的 **对数坐标图（Log Scale）** ——在这种图上，指数级暴涨的曲线看起来会是一条直观的斜线。图很快画出来了，很漂亮；但因为我懂代码，习惯性地点开了右上角的 `>_` 查看它底层写的 Python 源码，结果一眼看到它在代码数组里把 2015 年的 `N/A` **悄悄写死成了 `0.1` （即自行假设 2015 年估值为 1 亿美元）** ，而在回复我的文字里却对这个人为假设只字未提！
3. **第三步：拟合趋势线外推到 2030 年——抓到严重的读数幻觉** ：我接着让它用 `scipy.optimize.curve_fit` 拟合一条指数增长趋势线，外推预测 OpenAI 在 2030 年的估值并标在图上。它在正文回复里信誓旦旦地告诉我： *「根据指数趋势外推，OpenAI 到 2030 年的预计估值约为 **1.7 万亿美元（$1.7 Trillion）** 。」* 但我仔细一看它画出来的图表，2030 年那个红点旁边的标签明明印着 **`20271.7B` （即 20.27 万亿美元，整整差了十倍多）** ！我立刻在对话框里质问它：「把代码里算出来的那个变量单独 `print` 出来看看，到底是多少？你是不是在骗我？」它重新跑了一遍打印代码，发现确实是 **20 万亿美元** ，当场道歉认错。

这个例子把高级数据分析的优缺点展现得淋漓尽致： **它能帮你在几秒钟内完成写代码、拟合曲线和画图的全套工作，但你必须养成点开代码检查边界假设、并亲眼核对图表数字的习惯** ——如果你完全看不懂代码、也不去核对，这位粗心的初级分析师很容易在关键数字上把你带进沟里。

### Claude Artifacts：即席生成浏览器交互小应用与空间概念图（Mermaid）

如果说 ChatGPT 的强项是在服务端沙盒里跑 Python 画数据图，那么 Anthropic 的 **Claude** 则推出了另一项极有巧思的交互功能： **Artifacts（右侧实时渲染画布）** 。

当 Claude 生成前端代码（如 React 组件、HTML）或矢量流程图时，它不会只给你一堆冷冰冰的代码块，而是直接在聊天窗口右侧打开一个独立面板，把代码当场运行渲染成可交互的界面：

- **为了一篇课文，当场给你写一个专属闪卡 App** ：比如我把亚当·斯密的维基百科生平简介贴给 Claude，先让它提炼出 20 道问答复习题；接着我说：「请使用 Artifacts 功能写一个交互式闪卡（Flashcards）小应用来测验我这 20 道题。」Claude 当场写好一个完整的 React 应用并在右侧跑了起来——我可以点击卡片翻面看答案、点击“答对了 / 答错了”统计正确率、还能一键打乱卡片顺序或重置进度。在过去，我们必须去下载现成的软件（比如把题库导入 Anki）；而现在，大模型可以根据你手头正在学的一段资料，花一分钟现场为你一个人定制一个用完即走的专属小工具。
- **我最爱的私藏用法——把书本章节或源码变成「空间概念图（Conceptual Diagrams）」** ：就我自己而言，我并不是每天都用 Artifacts 写小游戏，但我极其高频地用它来 **画概念结构图** 。比如刚才读《国富论》第一卷第三章时，我把整章原文贴给 Claude，说了一句： **「请为这一章画一张概念逻辑图（Conceptual Diagram）。」** Claude 会自动编写 `Mermaid` 图表代码，在右侧直接渲染出一棵脉络极其清晰的树状架构图——从顶层的核心定理「分工受市场规模限制」，分叉出「内陆闭塞村庄（每人必须身兼数职）」与「水运发达地区（低成本贸易扩大市场半径）」，再一路推演出「为什么古埃及（尼罗河）、古印度（恒河）与地中海沿岸最早孕育出高度繁荣的人类文明」。像我这样偏视觉与空间化思考的人，看一眼这张空间拓扑图，整章的论证骨架就彻底印在脑子里了。你可以用这个办法给任何书籍章节、学术论文甚至复杂的代码库画结构图。

### 专业编程与「Vibe Coding（氛围编程）」：走向本地 Cursor Composer

前面展示了在网页端让 ChatGPT 和 Claude 写代码片段。但在我自己的日常工作中，我绝大部分时间都在写专业代码，而我 **从来不会去 ChatGPT 网页端复制粘贴代码** ——那样实在太慢了，而且网页端根本拿不到我本地项目的完整文件结构与上下文。

在专业开发场景下，我和目前行业里的大多数工程师一样，使用的是专门的本地 AI 代码编辑器 **[Cursor](https://www.cursor.com/)** （同类工具还有 Windsurf、VS Code Copilot 等），并在后台把模型切换为表现最稳的 `Claude 3.7 Sonnet` 。

回顾过去两年 AI 辅助编程的演进，我们经历了三个明显的台阶：

1. 最早是选中一行代码按 `Cmd + K` ，让 AI 局部修改这一行；
2. 接着是按 `Cmd + L` 打开侧边栏，让 AI 解释某一段代码；
3. 而现在，我们直接按 `Cmd + I` 打开 **Composer（开启 Agent 模式）** ——它就像一个驻扎在你本地代码库里的自主 Agent，能自己读取整个项目目录、同时跨多个文件增删代码、自己打开终端安装依赖并运行命令。

我给这种全新的写代码方式起了一个名字，叫 **「Vibe Coding（氛围编程）」** （没错，这个词大概就是我造出来的）。所谓 Vibe Coding，就是你几乎不再亲手敲具体的语法细节，而是靠在椅背上用自然语言告诉 Composer 你想要什么效果，把方向盘完全交给它，顺着感觉（Vibe）一路点接收（Accept）、盼着它跑通就行；万一真撞上它修不好的深层 Bug，因为所有源码文件都在本地，你随时可以退回传统编程方式自己上手改。

在视频里我现场演示了一个 3 分钟的小例子：我只写了五句话，让 Cursor Composer 从零初始化了一个 React 井字棋（Tic-Tac-Toe）网页游戏；跑起来之后，我随口对它说了一句\*「当 X 或 O 获胜时，给我加一点五彩纸屑（confetti）庆祝特效」\*——它不仅自动在终端运行 `npm install react-confetti` 安装了一个连我以前都不知道的特效库、改好了 `App.tsx` 和赢棋格子的高亮呼吸动画，甚至还主动提出要加一段获胜音效，自己建好 `public/sounds` 目录并从网上抓了一个 `victory.mp3` 音频文件配了进去！

## 7\. 多模态交互（一）：用嘴说话代替打字、「假音频」与原生「真音频」

前面我们聊的交互，输入和输出全都是文字（Text）。但人类最自然的交流方式显然不止打字——我们希望能直接开口跟模型说话、听模型开口回应，希望能直接给它看图片和视频。这就是大模型的 **多模态（Multimodality）** 能力。

![多模态底层机制对比：「假音频 vs 原生真音频」与「图像网格 Patch Token 化」](https://book.oiloil.org/assets/articles/how-i-use-llms/03-multimodal-audio-and-image-tokens.svg)

多模态底层机制对比：「假音频 vs 原生真音频」与「图像网格 Patch Token 化」

### 别再苦哈哈敲键盘了：我一半以上的提问都是靠嘴说的

先分享一个能立刻帮你省下大量力气的日常习惯： **能动嘴说，就别动手敲键盘。**

在我自己的日常使用中，坐在电脑前时我有大约 **50% 的提问是直接靠语音输入的** ；而到了手机上，这个比例更是高达 **80% 以上** ——因为用拇指在手机屏幕键盘上打字实在太慢了。

- **在手机端** ：打开 ChatGPT 等 App，直接点击输入框右下角的 **小麦克风图标** ，把你想问的话说出来，内置的语音识别就会瞬间把它转成文字填进输入框（只有遇到极个别容易识别错的冷门代码库名或专有名词时，我才会手动打字）。
- **在 MacBook 桌面端** ：因为网页版或桌面版输入框里有时没有直接转文字的小麦克风按钮，我在 Mac 上常年开着一款系统级的语音转文字小工具 **[Superwhisper](https://superwhisper.com/)** （同类好用的还有 Wispr Flow、MacWhisper 等）。我把它的全局唤醒快捷键绑在了键盘的 `F5` 上：不管当前光标停留在浏览器、编辑器还是终端里，按一下 `F5` 直接开口说话，说完再按一下 `F5` ，整段话就秒速变成准确的文字输进去了。反过来，如果你懒得用眼睛读长篇回复，也可以点击回答下方的 **Read Aloud（朗读）** 按钮，让模型把文字念给你听。

### 区分「假音频（Fake Audio）」与原生「真音频（True Audio）」

不过要注意，上面提到的「麦克风语音转文字」和「朗读文字」，在技术底层被我称为 **「假音频（Fake Audio）」** 。为什么叫假音频？因为核心的大语言模型自始至终只看到了 **纯文本 Token** ——只是在模型前面加了一个独立的语音转文字（Speech-to-Text）小模型，或者在模型后面接了一个文字转语音（Text-to-Speech）朗读器，大模型本身并没有真正“听见”你的语气，也不能直接用声音思考。

而真正革命性的技术，是 **原生「真音频（True Audio）」** ——也就是 ChatGPT 里的 **高级语音模式（Advanced Voice Mode）** 。

它是怎么做到的？工程师把连续的声音波形转换成显示不同频率分布的 **频谱图（Spectrogram）** ，再按时间切成一个个极小的时间窗片段，像给文字编码一样，把这些微小的声音片段归类匹配到大约 `100,000` 个“标准声音积木块”上，编成一套 **音频词表（Audio Tokens）** 。接着，直接把这些原生音频 Token 喂进大语言模型里训练！

这样一来，大模型内部直接接收的是音频 Token，预测输出的也是音频 Token， **全程没有任何文本中转** 。这赋予了它“假音频”永远做不到的能力：它能听懂你的语气、笑声和语速，也能按你的要求实时切换任意腔调、情绪和语速。

我在视频里现场连线演示了 ChatGPT 的高级语音模式与手机端 Grok 语音模式的对比：

- **ChatGPT 高级语音模式（反应极快、表现力强，但有时过于拘谨）** ：我问它「为什么天空是蓝色的，是因为反射了海洋的颜色吗？」，它刚解释完瑞利散射（Rayleigh scattering），我就打断它说：「别用普通腔调跟我说话，请用《星球大战》里尤达大师（Yoda）那种饱经沧桑的倒装句语气把知识传授给我！」它立刻惟妙惟肖地压低嗓音，用尤达大师的倒装语法重讲了一遍；我又让它瞬间切换成加勒比海盗腔调、变成讲睡前故事的绘本语气、甚至逼它用最快的速度从 1 数到 20，它全都对答如流。 但 OpenAI 给高级语音模式套上了非常紧的安全护栏，导致它有时显得 **过度敏感拘谨（Cagey）** ：比如我让它学一声牛叫，它乖乖地叫了一声\*“Moo~” *；可紧接着我问「那狐狸怎么叫（What does the fox say）？模仿一下狐狸叫」，它却突然翻脸拒绝说* 「抱歉，我无法模仿动物的声音或叫声，只能用语言描述」\*——哪怕我当场拆穿它说「我知道你的底层原理，你上一秒明明刚学了牛叫！」，它依然死咬着安全话术拒绝配合。
- **Grok 手机端语音模式（内置多种人格，彻底放飞自我）** ：如果你觉得 ChatGPT 太像个处处端着的优等生，想要更强的娱乐性，手机端 Grok App 右上角的语音模式简直是另一个世界。它内置了多个极其大胆的性格档位：切到 **Romantic（浪漫模式）** ，名叫 *Ara* 的女声 AI 会带着羞怯的停顿向你深情表白；切到 **Unhinged（暴躁失控模式）** ，我刚打声招呼说 *“Yo, bro”* ，它上来就是一顿毫不留情的毒舌咆哮（吐槽我们像“两只脑死亡的猴子大眼瞪小眼”）；切到 **Conspiracy（阴谋论模式）** ，它会满嘴跑火车地跟你畅聊特鲁多与卡斯特罗的身世传闻、51 区外星人、光照会、蜥蜴人甚至“英国女王其实是机器人”；至于最离谱的 **Sexy（性感撩人模式）** ，它一开口就描绘起“昏暗的房间里电流涌动……”，吓得我赶紧在两秒钟内掐断了演示。

### Google NotebookLM：把枯燥论文变成散步时听的双人播客

在音频模态下，还有一种我非常喜欢的创新交互形式：Google 推出的 **[NotebookLM](https://notebooklm.google.com/)** 。

用法非常简单：你在页面左侧上传任意参考资料（比如刚才那篇 30MB 的《Evo 2》DNA 基础模型论文、几个网页链接或长文档），把它们装进模型的上下文窗口。除了在中间发消息向文档提问外，页面右侧有一个 **Deep Dive Podcast（深度对话播客）** 生成按钮（你还可以提前填入自定义指令，指定播客重点聊什么角度）。

点一下生成，等上几分钟，NotebookLM 就会专门针对你上传的这几份材料，生成一段长达 20–30 分钟的 **双人谈话播客音频** ——男女两位 AI 主持人会像真人电台一样，有来有往、互相捧哏、用生动通俗的比喻把硬核论文拆解得妙趣横生。你甚至可以点击 **Interactive Mode（交互模式）** ，在听他们聊天的中途随时按下语音键“举手插话”提一个问题，两位 AI 主持人会当场解答你的疑问，然后再自然地聊回主线！

每当我想了解某个非本专业的新奇领域、或者手头攒了几篇长文章，准备出门散步或长途开车时，我就会用 NotebookLM 现场生成一期只有我一个人听的定制播客（人类播客主可不会刚好为你今天想看的那篇冷门论文录一期节目）。前阵子我甚至用它批量生成了一整季名为 **[《Histories of Mysteries（历史谜团）》](https://open.spotify.com/show/3K43356222111)** 的定制播客并传到了 Spotify 上，感兴趣的朋友可以去听听看 AI 播客现在的自然程度能做到什么水平。

## 8\. 多模态交互（二）：图像网格 Token 化、两步识图法与实时视频

讲完了声音，我们再来看视觉模态—— **图像（Images）与视频（Video）** 。

大模型一个原本用来预测文字的神经网络，为什么也能看懂照片？原理跟刚才的原生音频一模一样： **把图像也切成一维 Token 序列** 。最直观的做法是把一张图片画上矩形网格，切成一个个小方块（Image Patches），再从一套包含约 `100,000` 种基础视觉图案的“词表”里，给每个小方块匹配一个最接近的编号（转换成图像 Token）。

这件事在底层最令人赞叹的地方在于： **核心的 Transformer 神经网络甚至根本不知道自己此刻处理的 Token 到底是文字、声音频谱还是图像网格方块** ——在它眼里，万物皆是一维 Token 序列的统计规律；所有的模态差异，只在最前端的编码器（Encoder）和最末端的解码器（Decoder）里完成转换。这也是为什么现在原生支持文本、语音、图像同炉训练的模型常被称为 **Omni（全能多模态）模型** 。

![图像网格 Patch Token 化与解读体检单/配料表的「两步走」防幻觉工作流](https://book.oiloil.org/assets/articles/how-i-use-llms/08-image-patch-and-two-step-ocr-mobile.svg)

图像网格 Patch Token 化与解读体检单/配料表的「两步走」防幻觉工作流

### 我的日常识图铁律：「两步走（先转写表格肉眼核对，再提问解读）」

在日常生活中，我非常频繁地通过上传图片向大模型提问。但我有一条专门用来防幻觉的 **「两步走」实操习惯** ：

> **只要图片里包含密集的文字、数字或配料表，我第一步绝对不直接让它分析下结论，而是先命令它：「先把图里的文字/数值完整转写成纯文本或表格。」等我用肉眼对照原图扫一眼，确认它没有看走眼或漏字后，第二步再基于这段确认无误的文本向它追问解读。**

来看看我最近用这套方法解决的五个真实生活场景：

1. **解读补剂营养成分表（Nutrition Label）** ：还是前面提到的 Bryan Johnson 长寿冲剂，包装背面印着密密麻麻十几行成分与毫克数。我拍下照片发给 ChatGPT，第一步先让它完整转写成 Markdown 表格并核对数值；第二步再让它把所有成分按生理功能分组，并按「日常复合维生素里常见的安全基础成分」到「目前人体研究较少、需要留心的激进成分」进行排序，帮我建立起清晰的判断初稿。
2. **用截图快捷键逐段解读 20 页体检抽血报告（Blood Test）** ：前阵子我去做了全套抽血体检，医院发回来一份长达 20 页的 PDF 化验单，满篇缩写指标对普通人来说根本没法看。在 MacBook 上有一个极其顺手的系统截图快捷键 **`Ctrl + Shift + Cmd + 4`** ——按下后鼠标框选屏幕上的任意一块区域，图片就会直接存进系统剪贴板（不会在桌面留下一堆垃圾文件），然后切到 ChatGPT 直接按 `Cmd + V` 粘贴即可。我用这个快捷键把血脂（Lipid Panel）等化验单一块块截下来贴进去，确认它转写的各项指标数值和参考区间完全正确后，再结合我的年龄与日常状态让它逐项深度解读。因为常规血液指标属于互联网上医学资料最丰富、最标准化的高频知识，ChatGPT 的解读质量非常高，能帮你准备好去跟医生当面沟通时的核心问题清单。
3. **论文复杂数学公式提取（Math OCR）** ：读论文时看到一道长得很刁钻的微积分或代数表达式，不用自己费劲敲 LaTeX，直接 `Ctrl + Shift + Cmd + 4` 截图贴进去说「把它转成文本公式」，然后就能顺着让模型计算当 $x = \\pi$ 时的取值。
4. **扒皮日化用品配料表（高露洁牙膏成分筛查）** ：有一天我刷牙时看着手头的高露洁（Colgate）牙膏背面一大串化工名词，心里犯嘀咕：「我刷个牙到底往嘴里塞了些什么东西？」我拍下配料表上传给 ChatGPT，先转写确认，再问它两个问题：① 这些成分各自是干嘛的，哪些最安全、哪些存在争议？② **「如果我只在乎牙膏真正的清洁与防蛀核心功能，完全不在乎泡沫多不多、膏体漂不漂亮、颜色好不好看，可以把哪些多余的成分扔掉？」** 模型立刻帮我筛出了真正起效的 3–4 种核心成分，并指出里面一大半色素、甜味剂、发泡剂和增稠剂全是为了卖相好看加进去的。
5. **解释没看懂的网络谐音梗图（Meme）** ：朋友给我发了一张搞笑梗图——电线杆上只停着两只乌鸦，配文写着 *“Attempted murder”* （谋杀未遂）。朋友没看懂笑点在哪，我直接把图贴给 ChatGPT 说 `explain` ，它一秒钟就点破了双关语：在英语里，「一群乌鸦」的专属集合名词恰好叫 **`a murder of crows`** ；现在画面里只有两只乌鸦，还凑不够“一群（a murder）”，所以叫“未遂的鸦群（Attempted murder）”！

### 图像生成（DALL-E 3 / Ideogram）与手机实时视频交互

反过来，大模型也可以输出图片。比如你可以直接让 **DALL-E 3** 画一张唯美的「京都金阁寺（Golden Pavilion in Kyoto）」风景画，或者像我在视频里演示的那样：先让 ChatGPT 用联网搜索总结出今天的全球各大新闻头条（涵盖政治、医疗、国际与娱乐），再说一句「生成一张能概括今天世界动态的插画」，它就会结合上下文画出一张融合了多项新闻元素的画作（注意：在当时的架构下，这类生图并不是由语言模型直接吐出图像 Token，而是语言模型先在底层写一段详细的画面描述词 Caption，再转交给独立的 DALL-E 3 扩散模型去画图）。我自己平时不常画插画，但在给我的 YouTube 视频（比如《复现 GPT-2》）制作封面缩略图和网站小图标时，我非常喜欢混用 DALL-E 3 和另一款文字渲染能力很强的生图工具 **[Ideogram](https://ideogram.ai/)** 。

而在手机端 App 的高级语音模式下，如果你点击左下角的 **摄像机图标** ，就能直接开启 **实时视频对话（Video Mode）** ：

- 在视频里我拿起手机环顾四周：先拍墙上贴的黑色隔音海绵，它一眼认出我在测试房间回声并提供粘贴边角的建议；
- 接着我依次把摄像头对准桌上的两本书（《成吉思汗与今日世界之形成》与《别逗了，费曼先生》），它瞬间报出书名、作者与内容简介；
- 我把镜头对准桌上的小型空气检测仪，它不仅准确认出这是 **Aranet4 便携式二氧化碳检测仪** ，还直接读出屏幕上显示的 `713 ppm` ，告诉我室内低于 `800 ppm` 属于良好水平，超过 `1000 ppm` 才需要开窗通风；最后又一眼认出了墙上挂着的《指环王》中土世界地图。

虽然底层很可能只是按每秒一帧的频率把视频截成图片流喂给模型，但站在用户的角度，这种「指哪问哪」的流畅感非常神奇。像我这种整天写代码的重度键盘用户平时不一定用得上，但如果你要向父母或爷爷奶奶演示怎么用 AI，让他们拿着手机摄像头拍药瓶、拍家电按钮直接开口问，绝对是最零门槛的交互方式。此外，AI 视频生成赛道也在以肉眼可见的速度进化——比如网上有人让各家视频模型同题生成一段「丛林里的老虎」，其中 Google 的 **Veo 2** 和 OpenAI 的 **Sora** 都展现出了接近真实现场拍摄的惊人水准。

## 9\. 让大模型越来越懂你：记忆库、自定义指令与 Custom GPTs

最后，我想分享三项能大幅提升日常使用舒适度（Quality of Life）的个性化功能： **Memory（记忆库）** 、 **Custom Instructions（自定义指令）** 与 **Custom GPTs** 。

![个人定制化三件套：跨对话 Memory 记忆库、Custom Instructions 与 Few-Shot Custom GPTs](https://book.oiloil.org/assets/articles/how-i-use-llms/04-personalization-and-few-shot-gpts.svg)

个人定制化三件套：跨对话 Memory 记忆库、Custom Instructions 与 Few-Shot Custom GPTs

### 1\. ChatGPT Memory（跨对话记忆库）：自动拼接在开头的个人数据库

前面我们强调过，每次点击 `New Chat` 都会把上下文窗口清空。但如果你希望有些个人背景或偏好能跨对话保留下来，就可以利用 ChatGPT 的 **Memory（记忆）** 功能。

比如我和 ChatGPT 探讨「好莱坞电影真正的黄金巅峰期是哪个年代？」，它难得没有打太极，而是给出了一个很有态度的判断： *1990 年代末到 2000 年代初（在漫威宇宙等超级英雄大IP续集彻底接管好莱坞之前，既有《黑客帝国》《搏击俱乐部》这样的原创大片，也有丰富的独立电影）* 。我非常赞同这个观点，于是顺口回复道： **「完全同意，请记住我的这个电影品味偏好。」**

界面上立刻弹出了一行小字： `Memory updated（记忆已更新）` 。在底层，ChatGPT 实际上维护了一个独立的「个人记忆小数据库」——每当它自动触发或听你指令记下一条新信息，就会往这个文本列表里加一行简短的总结；而以后你每开启任何一个新对话，系统都会在后台 **把整个记忆列表自动拼接到上下文窗口的最开头** 。用久了之后，你会明显感觉到它越来越懂你的口味（比如之后让它给我推荐冷门好电影时，准确率高了非常多），而且你随时可以去设置里查看、修改或删掉某条不想保留的记忆（录视频时我本来想点开自己的记忆库给大家演示，结果扫了一眼发现里面攒了太多个人隐私细节，就不公开展示了）。

### 2\. Custom Instructions（自定义指令）：撕掉大模型的「HR 官腔」

如果你觉得大模型默认的说话语气太官方、太罗嗦，可以打开设置里的 **Customize ChatGPT（自定义指令）** ，全局修改它的性格与背景设定。

比如我自己就在「ChatGPT 应该具备什么特质」一栏里直截了当地写道：

> **「别像个公司里的 HR 业务伙伴（HR Business Partner）一样端着架子跟我说话，像正常人一样自然交流。我非常喜欢深入的原理阐释、知识背景与深刻洞察，只要有机会就多给我讲讲背后的来龙去脉。」**

同时，因为我最近在自学韩语，我还在自定义指令里加了一条： *「每当输出韩语时，请默认使用标准的礼貌敬语阶（해요체）」* ——否则模型一会用随便的半语，一会又用过于严肃的格式体，统一写进全局指令后就再也不用每次重复交代了。

### 3\. Custom GPTs 与少样本提示（Few-Shot Prompting）：我的韩语学习三件套

如果有一项特定任务你每天都要重复做十几次，每次都要写一大段相同的提示词和格式要求，最好的办法就是把它保存成一个 **Custom GPT** （左侧边栏随时点开即用）。

从技术本质上看，Custom GPT 并没有改变底层模型，它只是 **帮你把一套固定的长提示词（System Instructions）提前保存了下来，省去了每次复制粘贴的麻烦** 。但要想让你做的 Custom GPT 真正稳定好用，我有一个最核心的工程秘诀：

> **不要只用空泛的语言描述任务要求（Zero-shot，零样本），一定要在指令里附上 3–4 个具体的「输入 → 期望输出」标准范例，也就是构造一个少样本提示（Few-shot Prompt）！**

这跟带人类新员工是一个道理：你光口头讲十遍抽象规则，不如直接甩给他三份做好的满分样板卷，他看一眼样板就知道具体格式和颗粒度该怎么拿捏了。

我现在学韩语时，每天都离不开我自己用 Few-shot 方法做的 **三个专属 Custom GPT** ：

1. **韩语生词提取器（Korean Vocabulary Extractor）** ：我给它的系统指令里写了 4 个具体的输入输出范例——只要我扔进去一句韩语，它就会自动把句子里的生词提取出来、还原成词典里的基本原形（Dictionary Form），并严格按照 `韩语原形 ; 英文释义` 的分号分隔格式输出，方便我一秒钟复制粘贴进 Anki 闪卡软件里背诵。
2. **韩语深度语法拆解翻译器（Korean Detailed Translator）** ：说实话，自从有了大模型，我已经想不通为什么传统的在线翻译软件（比如 Google 翻译，或者韩国人常用的 Naver Papago）还有存在的必要。当你把一句韩语丢给传统翻译器时，它只给你一句冷冰冰的意译结果，把句子里的助词、词尾变化和微妙语气全吞掉了，你也根本没法追问它“为什么这里加这个词尾”。 而在我自制的这个 `Korean Detailed Translator` 里，我用类似 `<example>...</example>` 的 XML 标签在指令里写好了几组详尽的拆解示范：每次我输入一句韩语（比如 *“现在是下午三点，我想去我最喜欢的咖啡馆”* ），它会先给出整句翻译，接着把句子里的每一个词根、助词和贴在词尾表时态/语气的后缀逐一拆开对照解释；遇到没看懂的语法点，我还能在下面直接追问。如果你正在学任何一门外语，强烈建议你立刻扔掉传统翻译器，用 Few-shot 提示词给自己配一个专属的大模型拆解翻译器。
3. **韩综硬字幕截图翻译器（Korean Cap）** ：平时我看《单身即地狱》（ *Single's Inferno* ）等韩国综艺练习听力时，视频里的韩文字幕是直接烧录在画面像素里的（硬字幕），没法用鼠标复制。于是我专门建了一个叫 `Korean Cap` 的 Custom GPT，在指令里交代清楚上下文： *「我会发给你一张来自韩综《单身即地狱》的视频局部截图，里面有一句韩语台词。请按三步执行：① 先对图片做 OCR 识别提取出韩文字幕；② 给出整句英文翻译；③ 逐词拆解语法结构。」* 现在我看剧时（比如视频里演示的珍映 Jin-young 与瑟琪 Seul-ki 的对手戏片段），遇到任何没听懂的台词，直接按 `Ctrl + Shift + Cmd + 4` 框选画面底部的字幕区域，切到 `Korean Cap` 按 `Cmd + V` 粘贴回车，一秒钟就能拿到从 OCR 识别到逐词语法精讲的全套卡片！

## 10\. 总结：在大模型百花齐放的时代，建立你的工具全景图

回顾整场两小时的实战演示，你会发现今天的大语言模型生态就像一座热闹非凡、日新月异的「动物园」：

- **选对平台与模型档位** ：ChatGPT 作为最早入局的元老，依然是目前功能最齐全、综合体验最稳的默认首选；但各家都在特定赛道上长出了独门绝技——日常高频联网搜索我习惯用 **Perplexity** ，在浏览器里快速画概念逻辑图、写交互小组件我最爱 **Claude Artifacts** ，专业写代码我离不开本地的 **Cursor Composer（Vibe Coding）** ，把枯燥文献转成散步播客首选 **Google NotebookLM** ，而想体验完全不设防的语音聊天则可以试试手机端的 **Grok** 。
- **脑子里始终装着那张底层架构图** ：
	1. 记住你默认对话的只是一个 **「1 TB 的互联网有损压缩包」** ——切换话题时随手点 **New Chat** 保持上下文窗口干净，时刻留意左上角自己用的是免费缩水小模型还是付费旗舰大模型；
		2. 遇到硬核数学推导与复杂代码 Bug 时，果断切到经过强化学习训练的 **思考模型（Thinking Models）** ，给它几分钟时间跑完内部独白；
		3. 遇到近期动态或需要严谨证据的任务，主动启用 **联网搜索** 、 **Deep Research** 或 **直接上传 PDF/书籍章节** ，把真实一手资料塞进上下文窗口，并始终把 AI 的汇总报告当成需要核对引用的「初稿」；
		4. 遇到复杂计算或画图需求，确认模型调用了 **Python 解释器** （并留心检查它的代码假设与图表读数）；
		5. 全面拥抱 **多模态与个性化配置** ：用系统级语音输入（如 Superwhisper）代替敲键盘，用「先转写核对、再提问分析」的两步法解读体检单与配料表，并用 **Memory** 、 **自定义指令** 和带 **Few-shot 示例的 Custom GPTs** 把重复劳动彻底自动化；
		6. 留意 **电脑网页端与手机 App 端的功能差异** ：很多新能力（例如 ChatGPT 的实时视频对话、Grok 的多性格语音模式、输入框自带的语音转文字麦克风）往往只在手机 App 端提供，而在电脑端则需要搭配独立应用（如 Superwhisper、Cursor）才能发挥最大威力。

这些工具每个月都在快速迭代，各个功能在不同平台和手机/电脑端之间的分布也常常变动。但只要你理解了它们底层的运作逻辑，平时多动手跨平台尝试对比，就能把这一整套强大的 AI 工具箱真正变成你个人能力的放大器。
