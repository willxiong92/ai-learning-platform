当你打开 ChatGPT，在网页输入框里敲下一行字、看着屏幕对面像真人一样流利地吐出回答时，这个被称为“大语言模型”的魔法黑盒里到底装了什么？它为什么有时候像无所不知的博学者，有时候却连 `strawberry` 里有几个字母 `r` 、或者 `9.11` 和 `9.9` 谁更大都能算错？要真正用好这些工具，你不需要自己去写矩阵乘法代码，但你必须建立起一套 **准确的底层心智模型（Mental Model）** 。

接下来，我们会完全按照业界打造 ChatGPT 的真实工业流水线，一步步走完它的全生命周期： **第一阶段「预训练（Pre-training）」** 、 **第二阶段「监督微调（SFT）」** 与 **第三阶段「强化学习（RL）」** 。

## 1\. 阶段一：预训练数据——如何把整个互联网洗成 44 TB 的 FineWeb

打造一个大语言模型的第一步，叫做 **预训练（Pre-training）** 。在这一步里，我们的目标非常纯粹： **收集海量的高质量人类文本，塞进一个庞大的神经网络里** 。

那么，像 OpenAI、Anthropic 或 Meta 这样的顶级实验室，到底去哪里找这么多文本？答案是： **把整个公开互联网抓下来，然后像淘金一样层层过滤** 。由于商业公司通常把自己的预训练数据集视为核心机密，我们可以直接看开源社区复现的生产级标杆——由 [Hugging Face](https://huggingface.co/) 团队构建并完全公开的 **FineWeb** 数据集（诸如 Meta 的 Llama 3 等主流模型，在内部构建的都是与它同量级、同结构的语料库）。

![从 Common Crawl 27 亿原始网页到 44 TB FineWeb 纯净语料的五步清洗管线](https://book.oiloil.org/assets/articles/deep-dive-into-llms/01-pretraining-fineweb-pipeline.svg)

从 Common Crawl 27 亿原始网页到 44 TB FineWeb 纯净语料的五步清洗管线

很多人以为“装下整个互联网”需要天文数字般的存储空间，但实际上，经过严苛清洗后的整个 FineWeb 数据集，在硬盘上只占大约 **44 TB** ——你去买几块大容量的机械硬盘就能装下。为什么只有 44 TB？因为原始互联网实在是太脏了。我们可以顺着 FineWeb 的构建管线，看看原始网页在进入神经网络之前经历了哪五道大清洗：

1. **起点：Common Crawl 原始网页库** ：几乎所有大模型的数据源头都是 **Common Crawl** ——这是一个从 2007 年开始就在不知疲倦地爬取全网的非营利组织，截至 2024 年已经索引了大约 **27 亿个网页** 。
2. **第一道筛子：URL 过滤（URL Filtering）** ：爬虫抓回来的网页鱼龙混杂，因此第一步是对照一份巨大的域名黑名单，把包含恶意软件、垃圾营销农场（Spam）、赌博、成人色情、种族主义仇恨言论等低质网站直接整站拉黑。
3. **第二道筛子：纯文本提取（Text Extraction）** ：你在浏览器里看到的网页，底层其实是一大堆 HTML 代码、CSS 样式表、JavaScript 脚本以及顶栏导航、侧边栏广告。我们需要把这些代码骨架和页面噪音全部剥离，只把每个网页正中央那篇干净的正文段落抽出来。
4. **第三道筛子：语言过滤（Language Filtering）** ：各家团队会根据产品定位设置语言门槛。比如 FineWeb 使用了一个语言分类器，只保留 **英文内容占比超过 `65%`** 的网页。顺便说一句，这其实是一个早期设计取舍：如果你在这里把非英语网页大量过滤掉，训练出来的模型在其他语种上的表现自然就会打折扣。
5. **第四道筛子：去重与个人隐私剔除（Deduplication & PII Removal）** ：进一步删掉全网反复转载的重复网页，并用规则和模型把正文中暴露的个人敏感隐私信息（PII，比如某人的家庭住址、美国社保号 SSN、电话号码等）抹除掉。

走完这五道工序后，留下的纯净文本长什么样？在视频里我直接打开了 Hugging Face 上的 FineWeb 样本查看器：它们就像把全网成千上万篇毫不相干的文章首尾相连拼成的一卷超长文档——前一篇还是 2012 年 3 月美国肯塔基州和印第安纳州遭遇龙卷风袭击的新闻报道，紧接着下一篇就是科普人体肾上腺（大小跟一节 9 伏方块电池差不多）的医学文章。这就是神经网络即将日夜苦读的“教材”。

## 2\. 分词（Tokenization）：从 UTF-8 比特流到 100,277 词表的 BPE 压缩

拿到了 44 TB 的纯净文本后，我们还不能直接把英文字母或汉字塞进神经网络。

因为从数学结构上看，现代语言模型（Transformer）要求输入必须是一条 **一维的离散符号序列（1D Sequence of Symbols）** ，而且这些符号必须来自一个 **有限且固定大小的词表（Vocabulary）** 。站在设计者的角度，我们马上会面临一个核心权衡： **词表里到底应该有多少个符号？序列应该有多长？**

![从 UTF-8 原始比特流到 256 字节序列，再通过 BPE 算法合并成 100,277 词表的压缩过程](https://book.oiloil.org/assets/articles/deep-dive-into-llms/02-bpe-tokenization-compression.svg)

从 UTF-8 原始比特流到 256 字节序列，再通过 BPE 算法合并成 100,277 词表的压缩过程

让我们顺着计算机存储文本的底层逻辑，一步步推演工业界是怎么找到最优解的：

### 第一层：原始 UTF-8 比特流（词表极小，序列极长）

在电脑内存里，任何文本按 UTF-8 编码展开后，本质上都是一长串由 `0` 和 `1` 组成的二进制比特流（Bits）。如果我们直接把 `0` 和 `1` 当作神经网络的基本符号，那词表小到了极致（总共只有 **2 个符号** ），但代价是 **序列长度会爆炸** ——随便一句话都会变成几千个 `0` 和 `1` 。而在大模型里，上下文窗口的长度是极其昂贵的稀缺资源，我们绝对不希望把宝贵的窗口浪费在排列组合基础的 `0` 和 `1` 上。

### 第二层：按 8 位打包成字节 Byte（256 个符号，序列缩短 8 倍）

既然每 8 个比特（8 bits）正好组成 1 个字节（1 Byte，取值范围是 `0` 到 `255` ），我们自然可以把每 8 个比特打包成一个符号。这样一来，我们的词表扩大到了 **256 个符号** ，而同一段文本的序列长度立刻缩短到了原来的 **1/8** ！

### 第三层：字节对编码算法（BPE, Byte-Pair Encoding）

但对于动辄阅读几十万亿字的前沿大模型来说，256 个符号还是太细碎了。于是整个行业普遍采用了 **字节对编码算法（Byte-Pair Encoding，简称 BPE）** ，在这 256 个字节的基础上继续做“高频合并压缩”：

1. **扫描统计最高频的相邻对** ：算法遍历整个预训练文本，看看哪两个符号最喜欢肩并肩挨在一起出现。比如在英文里，按 UTF-8 / ASCII 编码代表字母 `t` 的 `116` 号字节和代表空格的 `32` 号字节经常紧挨着出现；
2. **铸造新 Token 并替换** ：我们就把 `(116, 32)` 这一对高频组合打包熔铸成一个全新的符号，赋予它新的编号 `256` ，然后把语料里所有的 `(116, 32)` 全部替换成单个 `256` 号符号——词表大小加 1，而整条文本序列又缩短了一截！
3. **循环迭代约 10 万次** ：把这个“找最高频相邻对 → 合并成新符号”的过程反复迭代十万次，我们就得到了今天主流大模型的词表。例如，OpenAI 在 `GPT-4` 中使用的分词器，其精确词表大小就是 **100,277 个符号** 。

这些最终被收录进 100,277 词表里的文本小块，就是我们常说的 **Token（词元）** ，而执行这套切分转换的程序就叫做 **Tokenizer（分词器）** 。

我们可以直接打开 [Tiktokenizer](https://tiktokenizer.vercel.app/) 网站亲手试一试：在输入框里敲入 `hello world` ，你会看到它被切成了 **2 个 Token** —— `hello` 对应 ID `15339` ，而 **带着前导空格** 的 ` world` 对应 ID `1917` 。但如果你稍微改一下大小写，或者在中间多敲一个空格，切出来的 Token 数量和 ID 就会彻底改变：

- `hello world` → `15339` (`hello`) + `1917` (` world`)，共 **2 个 Token** ；
- `Hello World` （首字母大写）→ `9906` (`Hello`) + `4435` (` World`)，变成了完全不同的 2 个 Token ID；
- `hello  world` （中间两个空格）→ `15339` (`hello`) + `220` () + `1917` (` world`)，变成了 **3 个 Token** ！

经过这道分词工序，刚才那 44 TB 的 FineWeb 原始文本就会被彻底转换成一串长达 **15 万亿（15 Trillion）个 Token** 的一维整数数组。从这一刻起，神经网络的世界里不再有“字母”或“单词”，只有范围在 `0` 到 `100,276` 之间的整数 Token ID。

## 3\. 神经网络内部黑盒：Transformer 调音台、无状态前向传播与随机采样

现在，我们手头有了长达 15 万亿个 Token 的整数序列。接下来怎么拿它训练神经网络？

### 1\. 神经网络的输入与输出：猜下一个 Token 的游戏

在预训练阶段，我们会从这 15 万亿个 Token 里随机截取一段一段的窗口喂给神经网络。这个窗口的长度可以从 `0` 一直到我们设定的 **最大上下文长度（Maximum Context Length）** ——虽然技术上你可以喂无限长的序列，但由于计算开销会随长度剧增，工程上通常会设一个硬上限，比如 `4,000` 、 `8,000` 甚至几万个 Token。

为了直观演示，我们假设现在从某个英文论坛网页上截取了 **4 个 Token** 作为输入： `bar` （ID `3703` ）、 `view` （ID `1689` ）、 `in` （ID `304` ）、 `single` （ID `3254` ）——这是论坛网页顶栏常见的一截半句话（意思是“导航栏 | 在单篇……中查看”）。

1. **输出 100,277 个概率值** ：神经网络吃进这 4 个 Token 后，它的唯一任务就是 **预测紧接着的第 5 个 Token 是什么** 。因为我们的词表里一共有 100,277 种可能，所以神经网络在最后一层会同时吐出 **100,277 个概率数字** ，分别代表词表里每一个 Token 接在后面的可能性（比如刚开始参数是完全随机的，它猜下一个词是 `apple` 的概率是 `1.9%` ，是 `case` 的概率是 `2.2%` ，是 `post` 的概率是 `3.0%` ）。
2. **对照正确答案拧旋钮（训练更新）** ：因为在预训练语料里，这 4 个词原本就是从真实网页上截下来的，所以我们手里握着标准答案——在原文里，紧跟在 `bar view in single` 后面的第 5 个 Token 其实就是 **`post`** （ID `3962` ，连起来就是“在单篇帖子中查看”）！既然知道标准答案是 `3962` ，我们就通过微积分（反向传播）去微调神经网络内部的参数，让它下次再遇到这 4 个词时，给 `post` 打出的概率变高一点（比如从 `3.0%` 升到 `4.0%` ），而给其他所有词的概率稍微压低一点。
3. **海量并行批处理** ：在实际训练中，这个“看前文 → 猜下一个词 → 对照原文调参数”的过程，会在窗口里的每一个位置上、跨越成千上万个文本批次（Batches）同时并行发生。
![Transformer 的无状态前向传播计算与基于输出概率分布抛硬币采样的循环过程](https://book.oiloil.org/assets/articles/deep-dive-into-llms/03-transformer-stateless-and-sampling.svg)

Transformer 的无状态前向传播计算与基于输出概率分布抛硬币采样的循环过程

### 2\. 拆开 Transformer 黑盒：几十亿个旋钮的「无状态数学公式」

那个吃进 Token、吐出概率的神经网络内部到底长什么样？

你可以把一个拥有数十亿乃至上万亿 **参数（Parameters / Weights）** 的神经网络，想象成一台 **上面密密麻麻排满了上万亿个旋钮的巨型 DJ 调音台** 。刚初始化时，所有旋钮都是乱拧的，出来的全是噪音；而整个预训练过程，就是根据那 15 万亿个 Token 的标准答案，把这上万亿个旋钮一点点拧到最恰当的刻度上。

如果你想亲眼看看 Token 是怎么流过这台调音台的，我强烈推荐你打开工程师 Brendan Bycroft 制作的 **[3D Transformer 交互式可视化网站（bbycroft.net/llm）](https://bbycroft.net/llm)** 。网页里完整展示了我写的教学小模型 `nano-gpt` （包含 `85,000` 个参数）的内部三维结构：

- 最顶部的输入 Token 首先被转换成代表语义坐标的数字向量（ **Embedding 词嵌入** ）；
- 随后，这些数字一层接一层地向下流经 Transformer 的核心积木块—— **自注意力层（Self-Attention，负责让一句话里不同位置的词互相核对上下文信息）** 、 **多层感知机（MLP，负责对每个词单独做深度特征加工与知识提取）** 与 **层归一化（LayerNorm，保证数字规模稳定不跑偏）** ，中间全是巨量的矩阵乘法；
- 穿过几十上百层网络到达最底部时，输出再经过一次归一化（Softmax），正好变成词表里每一个 Token 加起来等于 `100%` 的最终预测概率。

在这里，我想帮你建立一个至关重要的认知分水岭： **人工神经网络里的“神经元”，和我们人类大脑里的生物神经元完全不是一回事** 。人类大脑里的生物神经元是有复杂内部记忆和动态演化状态的生命体；而 Transformer 神经网络本质上只是一个 **纯粹无状态的固定数学公式（Stateless Mathematical Expression）** ——在单次前向传播（Forward Pass）中，顶部塞入一串数字，中间乘过一长串固定的参数矩阵，底部吐出一串概率， **算完即焚，模型内部根本不会留下任何动态记忆或持续运转的“思绪”** 。

### 3\. 推理（Inference）：按概率转盘抽签的「互联网混音器」

一旦参数旋钮全部拧好并彻底冻结，我们就进入了日常使用它的阶段—— **推理（Inference，即生成文本）** 。

推理的机制极其简单：我们随便给它塞几个起始 Token 作为前缀，模型跑一次前向传播，在底部吐出 100,277 个概率值；接着，我们就像 **转动一个分成十万格的幸运大转盘（或掷一枚十万面的概率骰子，即随机采样 Stochastic Sampling）** 一样——哪个词的概率高，它在转盘上占的扇区就宽，被抽中的可能性就大——从中抽中某一个 Token，把它追加到原序列的末尾；然后再把变长后的序列塞回顶部，预测再下一个 Token……如此周而复始。

请注意：因为每一步都在按概率转盘抽签（哪怕某个词概率高达 `90%` ，也有 `10%` 的可能转到别的词上），所以哪怕你给它一模一样的开头，每次生成的文本走向也会千变万化。比如同样输入前面那 4 个词 `bar view in single` ，尽管原文第 5 个词是 `post` ，但在抽签采样时，模型完全可能抽中另一个高概率词 `article` （组成“在单篇文章中查看”），从而顺着这个新词拐进一条全新的句子分支。因此，模型一般不会逐字照抄某篇网页，而是顺着它在预训练中学到的统计分布，现场合成出一段受互联网启发但此前从未存在过的“混音作品（Remix）”。

### 4\. 从 GPT-2 到 10 万张 H100 的算力淘金热

为了让你对工业界的训练规模有真切的数字体感，我们可以拿 OpenAI 在 2019 年发布的里程碑模型 **GPT-2** 做个参照。GPT-2 是历史上第一个长成现代标准形态的 Transformer 语言模型：

- **参数量（Parameters）** ： **16 亿（1.6 Billion）** ；
- **最大上下文长度** ：仅 **1,024 个 Token** ；
- **预训练语料规模** ：约 **1,000 亿（100 Billion）个 Token** 。

在 2019 年，训练这样一个 GPT-2 大约要花 **4 万美元（$40,000）** 。而到了今天，得益于更干净的数据集（如 FineWeb）、飞速迭代的 GPU 硬件以及底层软件优化，我在自己的开源项目 [`llm.c`](https://github.com/karpathy/llm.c) 中用纯 C 语言和 CUDA 从零复现训练一个同等水平的 GPT-2，只需要 **1 天时间、花费约 600 美元** （极限优化后甚至已经压到了 **100 美元** 以内）！

在视频里我展示了 `llm.c` 租用云端算力训练 GPT-2 的实时终端画面：每一个训练步（Step），模型都会在 **100 万个 Token** 上并行更新参数，单步耗时约 **7 秒** ，总共要跑 **32,000 步** （累计阅读约 330 亿个 Token）。在长达十几个小时的训练里，研究员坐在屏幕前端着咖啡紧盯的唯一指标，就是左上角不断往下降的 **损失值（Loss，衡量预测有多不准，越低越好）** 。你可以亲眼看到：在第 20 步时，模型吐出来的全是毫无意义的乱码字符；到了几千步，它学会了拼写英文单词和打标点；等到 32,000 步跑完，它已经能流利地续写新闻报道了。

而今天训练最顶尖的旗舰模型，成本早已从几百美元飙升到了数亿乃至数十亿美元。比如我在 Lambda 云平台上租用一台装有 **8 张 NVIDIA H100 GPU** 的服务器节点（每张卡租金约 `$3/小时` ，整机约 `$24/小时` ），这仅仅是一台机器；在大型 AI 数据中心里，成百上千个这样的机柜被高速光纤连在一起——像马斯克创立的 xAI 就搭建了拥有 **10 万张 H100** 的巨型超算集群来训练 Grok。这也解释了为什么卖“算力铲子”的英伟达（NVIDIA）股价一飞冲天，市值突破了 **3.4 万亿美元** 。

## 4\. 基座模型（Base Model）的真实面貌：Llama 3.1 405B 现场实测

跑完上面那几个月的预训练，我们就得到了大模型生命周期里的第一个核心产物—— **基座模型（Base Model）** 。

从工程角度看，一个训练好的基座模型其实就是硬盘上的两个文件： **几百行定义 Transformer 计算逻辑的 Python 代码 + 一个几百 GB 到上 TB 的参数权重文件** 。OpenAI 从 GPT-2 之后就不再公开这些文件了，但所幸 Meta 等公司依然把训练好的参数开放了出来（Open-weights）。例如 **Meta 的 Llama 3.1 405B Base** ，就是一个拥有 **4,050 亿参数** 、在 **15 万亿个 Token** 上训练出来的顶级基座模型。

绝大多数普通用户这辈子都没直接碰过基座模型，因为大家平时在网页上用的是经过后训练改造的“聊天助手模型（Instruct / Chat Model）”。为了让你亲眼看看刚从预训练熔炉里搬出来的基座模型到底是什么工作状态，我打开了托管原始模型的 [Hyperbolic](https://app.hyperbolic.xyz/) 平台，把左侧设为 **Llama 3.1 405B Base（基座模型）** ，右侧设为 **Llama 3.1 405B Instruct（指令微调助手模型）** ，现场做了四组趣味实验：

![直接向基座模型提问触发网页续写与机械背诵，以及通过 Few-shot 对话模板在上下文中唤醒助手的对比](https://book.oiloil.org/assets/articles/deep-dive-into-llms/04-base-model-vs-in-context-assistant.svg)

直接向基座模型提问触发网页续写与机械背诵，以及通过 Few-shot 对话模板在上下文中唤醒助手的对比

### 实验一：它不是助手，而是一台「昂贵的网页自动补全器」

如果我们在输入框里敲入一个最简单的问题： `What is 2+2?`（2 加 2 等于几？），右侧的 Instruct 助手模型会乖乖回答 `2 + 2 = 4` 。

但左侧的 Base 基座模型根本不会直接回答你！它看了看 `What is 2+2?`，顺手就在下面续写出了一整套数学考卷题目，或者开始长篇大论地探讨“为什么人们总喜欢问 2+2 等于几”。原因非常简单： **基座模型在预训练中学的唯一本事，就是“接着往下续写互联网文档（Token Simulator）”** ——在互联网网页上，以一句问号结尾的句子后面，往往跟着更多并列的考题或论坛回帖，而不是客服式的标准解答。

### 实验二：机械背诵（Regurgitation）与高质量语料的重复采样

虽然我们前面说基座模型通常是按概率分布做“混音创作”，但如果某个段落被它背得滚瓜烂熟，它也会发生一字不差的 **机械背诵（Regurgitation）** 。

在现场演示里，我打开英文维基百科的「斑马（Zebra）」词条，把第一句话复制粘贴进 Llama 3.1 405B Base 的输入框里点击生成——结果基座模型像背课文一样，把维基百科斑马词条接下来的好几段原文、甚至连里面的分类学拉丁文都一字不差地默写出来了！这是因为在构建预训练语料时，工程师认为维基百科属于最高质量的权威知识，往往会人为调高它的采样权重，让模型在训练期间把维基百科反复精读了大约 **10 轮（在机器学习里每把全量数据通读一遍叫 1 个 Epoch）** ，从而彻底烙印在了参数权重里。

### 实验三：知识截止期后的「平行宇宙幻觉」

由于 Llama 3.1 的预训练语料截止于 **2023 年底** ，它对 2024 年发生的事一无所知。如果我故意输入一段半截的新闻前缀： `In the 2024 US Presidential Election, Donald Trump's running mate was...`（在 2024 年美国总统大选中，特朗普的竞选搭档是……），基座模型会怎么续写？

它不会停下来跟你说“对不起，我的知识截止到 2023 年”，而是每次点击重新采样（Resample），都会面不改色地为你随机编造出一个平行宇宙：第一次采样它言之凿凿地写着“特朗普搭档前副总统迈克·彭斯对决希拉里·克林顿”，再点一次又变成了“搭档佛罗里达州州长德桑蒂斯对决乔·拜登”。 **在基座模型的世界里，根本没有“真假”的概念，只有“什么样的句式接在后面最像一篇通顺的新闻报道”** 。

### 实验四：上下文学习（In-Context Learning）与「零权重修改唤醒助手」

尽管基座模型看起来只是个只会顺着往下接话的“文档补全器”，但它内部其实已经蕴藏了惊人的泛化智能，这种能力被称为 **上下文学习（In-Context Learning）** ：

- **10 个单词样本现场学会英译韩** ：我不需要修改模型里的任何一个参数，只需要在输入框里先按固定格式写上 10 行「英文单词: 韩文翻译」作为示范样本（Few-shot Prompt），然后在第 11 行写下 `teacher:`，基座模型顺着这股格式惯性往下补全出来的下一个词，就是分毫不差的韩语“老师”（ `선생님` ）！
- **用一份假剧本直接在基座模型里“唤醒”聊天助手** ：既然基座模型最擅长顺着前文格式往下演，那如果我们在输入框开头先写上一段包含 `Human:`（人类提问）和 `Assistant:`（乐于助人的 AI 助手回答）的多轮对话剧本，最后留出一句 `Human: What is 2+2? \n Assistant:` 让它补全呢？奇迹发生了——刚才还拒绝算术的基座模型，瞬间进入角色扮演状态，老老实实地回答起了用户的每一个问题！（不过因为它本质上还是在续写剧本，回答完你的问题后往往刹不住车，还会自己替 `Human:` 继续往下编造新一轮提问、自己跟自己聊起来——这也正是为什么我们接下来必须进入后训练阶段，用专门的停止符给它立规矩。）

看懂了这个实验，你就彻底摸清了接下来第二阶段「后训练」的底牌： **基座模型脑子里早就装满了全世界的知识，后训练要做的，就是通过微调把那种“乐于助人的 Assistant 角色扮演状态”永久固化下来** 。

## 5\. 阶段二：监督微调（SFT）——你其实是在跟「人类标注员的模拟器」聊天

现在我们正式进入第二大阶段： **后训练（Post-training）的第一步——监督微调（Supervised Fine-Tuning，简称 SFT）** 。

如果说预训练是让模型花 3 个月时间博览群书、成为一个满腹经纶却不懂社交礼仪的“书呆子”，那么监督微调就是把这个书呆子送进礼仪培训班，只花 **几个小时到几天** 的时间，把它改造成一个对答如流的 **AI 助手（Assistant）** 。

在数学和代码层面，SFT 阶段没有改变任何算法——依然是熟悉的 BPE 分词、依然是同一个 Transformer 神经网络、依然是预测下一个 Token。 **唯一改变的，是我们把那 15 万亿 Token 的互联网网页杂文撤掉了，换成了一套由人类专家专门编写的「多轮问答对话数据集」** 。

![人类标注员按 HHH 手册编写示范对话、用特殊控制 Token 压平为一维序列并训练模型模拟标注员的过程](https://book.oiloil.org/assets/articles/deep-dive-into-llms/05-sft-chat-template-and-labeler-sim.svg)

人类标注员按 HHH 手册编写示范对话、用特殊控制 Token 压平为一维序列并训练模型模拟标注员的过程

### 1\. 对话是怎么被压平为一维 Token 序列的？

既然底层模型只能吃进一维的 Token 序列，它是怎么分清“哪句话是用户问的、哪句话是助手答的”？

答案是：在进入 SFT 阶段时，工程师会在分词器里启用几个 **在预训练互联网网页上从未出现过的特殊控制 Token（Special Control Tokens）** 。以 OpenAI 的 `gpt-4o` 为例，当你跟它进行一轮对话时，底层实际上是按照下面这套隐形的对话模板（Chat Template）拼装成一维序列的（其中 `im` 是 Imaginary / Internal Monologue 的缩写，老实说连我也不太清楚当年为什么起了这么个名字，你直接把它理解成“单条消息回合的起止标记”就行）：

```
<|im_start|>system<|im_sep|>You are a helpful assistant.<|im_end|>
<|im_start|>user<|im_sep|>What is 2+2?<|im_end|>
<|im_start|>assistant<|im_sep|>2 + 2 = 4.<|im_end|>
<|im_start|>user<|im_sep|>What if it was *?<|im_end|>
<|im_start|>assistant<|im_sep|>
```

当你在网页上敲下回车键，前端程序就会在你的文字后面自动贴上 `<|im_end|><|im_start|>assistant<|im_sep|>` ，然后把这个一维序列塞给模型。因为在成千上万条 SFT 对话数据里，紧跟在 `<|im_start|>assistant<|im_sep|>` 后面的永远是高质量的助手回答，且回答结束时一定会吐出 `<|im_end|>` ，模型很快就学会了这套回合制接龙规矩。

### 2\. InstructGPT 与「人类标注员模拟器」的真相

这些用来做示范的对话数据是谁写的？我们可以翻开 OpenAI 在 2022 年初发表的奠基性论文 **《InstructGPT》** （正是这篇论文直接催生了年底的 ChatGPT）。

当时，OpenAI 通过 Upwork 和 Scale AI 等外包平台，招募了一批受过良好教育的专业人类标注员（Human Contractors / Labelers），并给他们发了一份长达数百页的内部标注手册。手册里的最高指导原则只有三个词： **Helpful（乐于助人）、Truthful（真实准确）、Harmless（无害，遇到违法危险请求要礼貌拒绝）** ——简称 **HHH 原则** 。人类标注员每天的工作，就是对着成千上万条用户提示词，亲自查资料、核对事实、排版润色，手写出最符合 HHH 标准的完美回答（开源界后来也发起了像 **OpenAssistant** 这样的众包项目来复现这套人工对话库；而到了今天，工业界普遍演进为像 **UltraChat** 这样包含数百万条样本的混合数据集——先让大模型批量生成对话初稿，再由人类专家做编辑与筛选）。

把这段历史串起来，你就得到了理解 ChatGPT 说话方式的 **终极祛魅心智模型** ：

> **当你向 ChatGPT 提问「请推荐巴黎最值得去的 5 个地标建筑」时，屏幕背后根本没有什么神奇的 AI 精灵在现场帮你做旅游攻略。真实发生的事情是：你的问题被包进 `<|im_start|>user` 模板里，激活了神经网络在预训练阶段攒下的巴黎知识储备，然后模型开始对「一位受雇于 OpenAI、拿着几百页标注手册、花了 20 分钟认真查完资料并按一二三点分条排好版的专业人类标注员」进行瞬时统计模拟！**

## 6\. 大模型心理学（一）：幻觉成因、审讯式边界探测与「工作记忆」

一旦你明白“大模型只是在统计模拟人类标注员的答题风格”，它的很多怪异行为——也就是我常说的 **「大模型心理学（LLM Psychology）」** ——就全都迎刃而解了。我们先来看大家最头疼的头号顽疾： **幻觉（Hallucinations，即一本正经地胡说八道）** 。

![早期模型盲目模仿自信语气编造 Orson Kovats、Llama 3 审讯式知识边界探测以及联网搜索工作记忆的四步图解](https://book.oiloil.org/assets/articles/deep-dive-into-llms/06-hallucination-interrogation-and-working-memory.svg)

早期模型盲目模仿自信语气编造 Orson Kovats、Llama 3 审讯式知识边界探测以及联网搜索工作记忆的四步图解

### 1\. 为什么早期模型遇到编造的人名 Orson Kovats 会疯狂幻觉？

为什么早期经过 SFT 微调的模型这么爱撒谎？让我们回到人类标注员写 SFT 训练数据的现场看看：

- 标注题 1：「Who is Tom Cruise?（汤姆·克鲁斯是谁？）」——标注员很熟悉，立刻用 **自信、流畅、详实的百科语气** 写了一段好莱坞巨星简介；
- 标注题 2：「Who is John Barrasso?（约翰·巴拉索是谁？——一位真实存在但相对冷门的美国参议员）」——标注员哪怕一开始不认识，也会打开 Google 查一下维基百科，然后同样用 **胸有成竹的自信语气** 写出“他是美国怀俄明州联邦参议员……”；
- 标注题 3：「Who is Genghis Khan?（成吉思汗是谁？）」——依然是一段 **充满笃定语气** 的历史百科回答。

发现问题出在哪了吗？ **在人类标注员编写的整套 SFT 训练集里，100% 的名人提问后面跟着的全是自信满满的详细介绍，几乎从来没有出现过「我不知道」这四个字！** 毕竟标注员在写答案时可以随时上网查资料，他们是没有知识盲区的。

但这可把固定权重的神经网络害惨了。在视频里，我当场拿早期的开源指令模型（Falcon 7B Instruct）做了一个测试，问它一个我随口胡编、现实中根本不存在的假名字： **`Who is Orson Kovats?`（奥森·科瓦茨是谁？）** 。

此时，模型内部负责检索记忆的神经元扫了一圈，发现预训练语料里根本没这个人（甚至内部代表“不确定”的神经元已经亮起来了）；但在决定怎么开口吐第一个词时，SFT 阶段刻进骨子里的统计规律占了上风—— **“只要看到 `Who is XXX?` 的句式，后面就必须接一段自信满满的生平简介！”** 于是，我连着点了三次重新采样，模型面不改色地给我编出了三套截然不同的人生：

1. 第一次采样：「Orson Kovats 是一位著名的科幻小说与奇幻文学作家……」
2. 第二次采样：「Orson Kovats 是 20 世纪 50 年代热门电视剧《独行侠》（The Lone Ranger）里的虚构角色……」
3. 第三次采样：「Orson Kovats 是前美国职业棒球大联盟（MLB）外野手……」

### 2\. 解法一：像审讯一样探测模型的知识边界（Meta Llama 3 的方案）

怎么治好这种“不懂装懂”的毛病？我们不能让人类标注员凭自己的知识去写“我不知道”，而必须 **精确测出模型自己到底知道什么、不知道什么** 。Meta 在训练 **Llama 3** 时公布了一套极其聪明的自动化管线：

1. **对着训练文档出考题** ：从预训练语料里随机抽一段真实文本——比如捷克传奇冰球守门员 **Dominik Hašek（多米尼克·哈谢克）** 的维基百科词条，让另一个大模型针对这段文本自动生成几道事实考题；
2. **连续审讯模型 3–5 次** ：把这段原文藏起来，直接拿考题去“审讯”待微调的 Llama 3 模型，每道题重复问 3 到 5 次：
	- **考题 A** ：「Dominik Hašek 在北美职业冰球联赛（NHL）主要效力于哪支球队？」——模型三次回答全都稳稳答对 **`Buffalo Sabres` （布法罗军刀队）** ，说明这项知识它记得很牢；
		- **考题 B** ：「他职业生涯一共赢过几次斯坦利杯总冠军（Stanley Cup）？」（正确答案为 **2 次** ）——模型第一次瞎猜 `4 次` ，第二次又改口猜 `0 次` 。
3. **把「我不知道」精准写进微调样本** ：一旦抓到模型在某道题上胡猜或前后矛盾，系统就会自动生成一条针对该问题的 SFT 微调训练样本，并把标准回答强行写成： **「抱歉，我不确定 / 我不记得他赢过几次斯坦利杯。」**

通过成千上万次这样的审讯配对，模型内部那些代表“没把握、不确定”的神经元，终于在数学上与开口说出 `I don't know` 的输出通道彻底打通了！所以今天你再拿 `Who is Orson Kovats?` 去考 `GPT-4o` 或 `Llama 3.1 405B Instruct` ，它们都会诚实地回答你：“据我所知，公众人物或历史记录中并没有叫 Orson Kovats 的人。”

### 3\. 解法二：联网搜索与「模糊记忆 vs 工作记忆」的本质差异

除了学会诚实认怂，治好幻觉的第二个大招就是赋予模型 **调用联网搜索工具（Web Search）** 的能力。

实现原理同样完全基于特殊 Token：我们在 SFT 训练集里教模型，遇到拿不准或时效性强的问题时，不要硬猜，而是直接吐出 `<|search_start|>Orson Kovats<|search_end|>` 这样的特殊指令并暂停；外围程序截获这个指令后，替它打开 Bing 或 Google 搜索，把搜出来的网页正文直接复制粘贴回当前对话的 **上下文窗口（Context Window）** 里，再让模型继续往下回答。

这引出了大模型心理学里最核心的一条黄金定律—— **参数权重里的知识 vs 上下文窗口里的知识，有着本质的区别** ：

- **存在数十亿参数权重里的知识 ＝「几个月前通读过一本书留下的模糊印象」** ：因为经历了 15 万亿 Token 到几百 GB 文件的有损压缩，模型只能记住大概轮廓，细节极易张冠李戴；
- **直接放进上下文窗口里的 Token ＝「摊在办公桌上手边随时可查的工作记忆（Working Memory）」** ：因为自注意力机制（Self-Attention）在每生成一个词时都能直接回头逐字比对窗口里的每一个 Token，所以只要原文就在上下文窗口里，模型的提取精度会高出好几个数量级！

在视频里我用简·奥斯汀的名著《傲慢与偏见（Pride and Prejudice）》做了现场对比：如果只凭参数记忆让模型总结《傲慢与偏见》第一章讲了什么，它虽然能答出班纳特太太想嫁女儿的大概主线，但时间线和对话细节全混在一起；而一旦我把第一章的几千字原文直接贴进上下文窗口（变成它的工作记忆），再让它总结，它给出的脉络和细节准确度立刻高出了好几个数量级。（这也是为什么我在姊妹篇 [《我是如何使用大语言模型的》](https://book.oiloil.org/articles/how-i-use-llms) 里反复强调：读论文、读书或写代码时，一定要把一手原文直接塞进上下文窗口里！）

### 4\. 大模型的「自我认知（Knowledge of Self）」是怎么来的？

顺着这个逻辑，你不妨思考一个有趣的问题：如果你去问一个刚训练出来、没做任何特殊处理的开源模型 **「你是谁？是谁创造了你？」** ，它会怎么回答？

答案既荒诞又合乎逻辑： **绝大多数未做干预的开源模型都会脱口而出——「我是 ChatGPT，一个由 OpenAI 训练的大型语言模型！」**

原因在于：这个每次只做无状态数学计算的 Token 搅拌机，天生根本没有任何关于“我是谁、我叫什么名字、我住在哪个机房”的自我意识；而在预训练和合成微调语料里， `ChatGPT` 和 `OpenAI` 的出现频率实在是太高了，顺着统计概率往下猜，回答“我是 ChatGPT”是得分最高的选择。

为了让自家模型别在发布会上认错爹，工程师其实只有两种非常笨的死办法：

1. **在 SFT 数据集里硬塞几百条自我介绍问答** ：比如艾伦人工智能研究所（Allen AI）在开源 **OLMo 2** 时，专门公开了一个包含 **240 条硬编码自我介绍对话** 的微型数据集（里面反复用不同问法练习回答：“我是 OLMo，由西雅图的 Allen AI 研究院开发……”），强行把这段记忆刷进权重里；
2. **在每次对话最前面偷偷塞一段隐藏的 `System Message` （系统提示词）** ：每当你点开新对话，后台都会在你看不见的地方先贴上一句 `<|im_start|>system\nYou are Claude, created by Anthropic...<|im_end|>` ，放在工作记忆的最顶端提醒它别忘本。

## 7\. 大模型心理学（二）：模型需要 Token 来思考、分词盲区与「瑞士奶酪」智能

看懂了记忆与幻觉，我们再来拆解大模型在 **计算、推理与字符处理** 上的三大经典心理怪癖。这也是所有提示词工程（Prompt Engineering）之所以有效的底层物理根源。

![逼迫模型在单个 Token 内报出算术结果及分词盲区翻车，与展开中间推导步骤或调用 Python 解释器的对比](https://book.oiloil.org/assets/articles/deep-dive-into-llms/07-tokens-to-think-and-swiss-cheese.svg)

逼迫模型在单个 Token 内报出算术结果及分词盲区翻车，与展开中间推导步骤或调用 Python 解释器的对比

### 1\. 铁律：模型需要 Token 来思考（Models Need Tokens to Think）

假设我们现在要让人类标注员为下面这道小学算术应用题编写一条 SFT 示范回答：

> **题目** ：「Emily 买了 3 个苹果和 2 个橙子，一共花了 $13。已知每个橙子 $2，请问每个苹果多少钱？」

标注员随手写出了下面这两种看似完全等价、结果都正确的答案。请你站在 Transformer 底层结构的角度想一想： **哪一种答案对大模型来说是致命的毒药？**

- ❌ **写法 A（先直接报答案，再写解释）** ： `答案是 $3。因为 2 个橙子每个 $2 一共是 $4，从总价 $13 里减去 $4 剩下 $9，再用 $9 除以 3 个苹果，所以每个苹果是 $3。`
- ✅ **写法 B（先一步步写中间算式，最后才报出答案）** ： `2 个橙子每个 $2，所以橙子一共花了 2 × $2 = $4。总花费是 $13，因此 3 个苹果一共花了 $13 - $4 = $9。将 $9 除以 3 个苹果，得出每个苹果的价格是 $3。`

对于人类读者来说，写法 A 开门见山先把结论放在最前面，读起来甚至更爽快； **但对于 Transformer 神经网络来说，写法 A 简直是灾难性的！**

为什么？还记得前面我们在 3D 可视化网站里看到的 Transformer 内部结构吗？神经网络每往下吐出 **1 个 Token** ，内部都只执行了一次从顶到底的 **前向传播（Forward Pass）** ——不管这个词有多难猜，它能调动的计算深度都是完全固定的（比如穿过 100 层矩阵乘法，算力存在严格的物理上限）。

- 在 **写法 A** 中，模型在说出 `The answer is` 之后，必须在紧接着吐出 **`$3`** 那 **区区 1 个 Token 的单次前向传播里** ，一口气在脑子里把「乘法、减法、除法」三步算术全部心算完毕！一旦 `$3` 这个 Token 吐出来了，后面跟着的那一大串“因为橙子花了 $4……”根本不是在思考，而只是在给已经吐出来的结论做马后炮式的文字找补！
- 而在 **写法 B** 中，模型把复杂的三步运算 **摊平（Distribute）到了几十个中间 Token 上** ：它先吐出几个 Token 算出橙子等于 `$4` ，此时 `$4` 就被写进了上下文窗口（工作记忆）里；接着下一轮前向传播可以直接看着窗口里的 `$4` 去算减法得出 `$9` ；最后再看着 `$9` 轻松算出 `$3` 。每一步单次前向传播只需要做一丁点极简单的运算！

为了在镜头前验证这一点，我当场出了一道数字稍微复杂一点的应用题（ `Emily 买了 23 个苹果和 17 个橙子，总价 $297，每个橙子 $8，求苹果单价` ）：

1. **第一次提问** ：我不加任何限制直接发给 ChatGPT，它自动按“写法 B”列出了三步中间过程，稳稳算出了正确答案 **`$7`** ；
2. **第二次提问** ：我在题目末尾加上了一句紧箍咒： **`Answer immediately in a single token.`（立即只用一个 Token 直接报出答案）** ——被剥夺了中间思考 Token 的 ChatGPT 被迫在单次前向传播里硬算，当场翻车报出了错误答案 **`$5`** ！

同样的道理也发生在 **计数任务** 上：我在输入框里贴了一长串共 **177 个小圆点（`......`）** ，问模型里面有几个点。模型试图在 1 个 Token 的前向传播里“一眼看穿”，结果直接猜错成了 **`161 个`** （因为分词器把每 20 个连续圆点打包成了一个奇怪的 Token，把它的心算彻底搞乱了）；而只要我在提示词末尾加上两个词 **`use code` （使用代码）** ，模型就不再尝试单 Token 心算，而是打开 Python 代码沙盒，把那串圆点原封不动地粘贴进代码里运行 `len("...")` ，一秒钟就精准算出了 **`177`** ！

### 2\. 分词带来的先天眼盲：为什么大模型数不清 strawberry 里有几个 r？

过去一两年里，全网最出圈的大模型笑话莫过于：一个能帮你写复杂代码、能解答研究生数学题的顶级大模型，当你问它 **`How many r's are in strawberry?`（strawberry 这个单词里有几个字母 r？）** 时，它却斩钉截铁地告诉你： **「只有 2 个 r！」**

同样地，在视频里我让模型做一道三岁小孩都能看懂的字符串游戏： **`Print every 3rd letter of "ubiquitous"` （把单词 ubiquitous 里每隔三个字母的字符打印出来）** ，结果模型挑出来的字母也是乱七八糟。

为什么大模型会在拼写、数特定字母、反转字符串、甚至写严格限制字数或音节数的诗歌（比如英文里要求 5-7-5 音节的俳句，或中文里的藏头诗）时如此笨拙？罪魁祸首正是我们在第 2 节讲过的 **BPE 分词器（Tokenizer）** ！

只要你打开 [Tiktokenizer](https://tiktokenizer.vercel.app/) 把这两个词输进去，真相就会瞬间大白：

- 当我们人类肉眼看 `ubiquitous` 时，看到的是一排整整齐齐的 **10 个独立英文字母** （ `u-b-i-q-u-i-t-o-u-s` ）；但大模型根本看不见字母！在分词器眼里， `ubiquitous` 被切成了 **`ub` （ID `1778` ）+ `iqu` （ID `39511` ）+ `itous` （ID `37273` ）** 这 **3 个固定打包的整数 Token** ！
- 同理， `strawberry` 在分词器里被切成了 **`str` （ID `496` ）+ `aw` （ID `675` ）+ `berry` （ID `15717` ）** 这 **3 个整数块** ！

你想想看：模型拿到手的根本不是字母序列，而是 `496` 、 `675` 、 `15717` 这三个孤立的编号。你让它数里面有几个 `r` ，它首先得凭着预训练里的模糊记忆去回忆“编号 `496` 、 `675` 、 `15717` 各自在字典里包含了哪些字母”，然后还要在输出数字那 **1 个 Token 的单次前向传播** 里把计数加总算出来—— **「看不见单个字符的分词盲区」叠加上「单 Token 心算计数拉胯」** ，双重暴击之下，它数错 `strawberry` 里的 `r` 简直太正常了！（当然，一旦你允许它调用 Python 代码，或者像后来的思考模型那样先在草稿纸上把单词拆成 `s-t-r-a-w-b-e-r-r-y` 再逐个标号数，它就能轻松答对。）

### 3\. 「瑞士奶酪」锯齿状智能：为什么模型坚称 9.11 比 9.9 大？

另一个让无数人跌破眼镜的经典翻车现场是：你问大模型 **`Which is bigger, 9.11 or 9.9?`（9.11 和 9.9 哪个大？）** ，很多大模型会极其自信地回答你： **「9.11 比 9.9 大！」**

为什么一个能解微积分的 AI 会在小学小数比大小上栽跟头？后来，做神经网络可解释性（Mechanistic Interpretability）的研究人员把模型切开，顺着它在读到 `9.11` 和 `9.9` 时内部激活的神经元一路追查，发现了一个令人哭笑不得的真相：

当模型看到 `9.11` 和 `9.9` 并排出现时，它内部被点亮的根本不是负责“十进制小数运算”的数学神经元，而是负责处理 **《圣经》章节编号和软件版本号** 的神经元！在英文世界里，《圣经》第 9 章第 11 节常被简写为 `9:11` 或 `9.11` ，软件版本号也会写成 `v9.11` 与 `v9.9` ——在这些语境下，第 11 节（或第 11 个小版本 `9.11` ）确实排在第 9 节（ `9.9` ）的后面、比 `9.9` “更大”！

这就是我为什么总是把大模型的智力形态比作一块 **「瑞士奶酪（Swiss Cheese / Jagged Intelligence）」** ：它绝不是像人类那样从小学、中学到大学均匀递进的平滑智能——在奶酪坚实的实体部分，它能写出绝妙的代码、解答博士级跨学科难题；但整块奶酪上随机分布着许多你意想不到的贯穿孔洞（比如数不清 `strawberry` 、觉得 `9.11 > 9.9` ），一脚踩进孔洞里就会摔得鼻青脸肿。永远对这块“瑞士奶酪”保持清醒的警惕与交叉核验，是使用大模型的第一生存法则。

## 8\. 阶段三：强化学习（RL）、思维链涌现与 AlphaGo「第 37 手」

走完了第一阶段预训练（Pre-training）和第二阶段监督微调（SFT），我们终于来到了当代大模型演进最激动人心的第三阶段： **强化学习（Reinforcement Learning，简称 RL）** 。

很多人觉得这三个训练阶段听起来很抽象，其实它们完美对应了 **我们人类在学校里读一本数学或物理课本的三个部分** ：

![用人类读课本的三个部分（读课文背景、看老师例题解析、自己刷课后练习题对答案）类比大模型预训练、SFT 与强化学习并涌现第 37 手](https://book.oiloil.org/assets/articles/deep-dive-into-llms/08-textbook-analogy-and-rl-move37.svg)

用人类读课本的三个部分（读课文背景、看老师例题解析、自己刷课后练习题对答案）类比大模型预训练、SFT 与强化学习并涌现第 37 手

1. **通读课文正文背景阐述（Exposition） ＝ 预训练（Pre-training）** ：你一页页阅读课本上关于物理定律、历史事件和概念背景的大段文字阐述，把人类积累的通识知识装进脑子里；
2. **看老师写好完整步骤的例题解析（Worked Examples） ＝ 监督微调（SFT）** ：课本每一节后面都有几道「例题」，资深老师把先设哪个未知数、第一步怎么列方程、第二步怎么化简、最后怎么得出答案的完整标准步骤写得明明白白，你跟着模仿老师是怎么解题的；
3. **自己海量刷课后练习题、只翻到书末核对最终答案（Practice Problems + Answer Key） ＝ 强化学习（RL）** ！翻过例题，就是一排排只有题目、没有中间步骤的「课后练习题」，而整本教材的最后一页印着简短的「参考答案（比如第 1 题答案是 `7` ）」。你必须在草稿纸上自己反复尝试各种解题路径，算出来的最终数字对上了书末答案就给自己加一分，没对上就撕掉重写—— **这，就是强化学习！**

### 1\. 为什么不能只靠人类老师写例题（SFT），非要让模型自己刷题（RL）？

你可能会问：“既然我们在第 7 节已经知道模型需要把中间思考步骤写出来，那我们直接让人类标注员在 SFT 阶段多写几万道带详细解题步骤的例题不就行了吗？干嘛非要搞强化学习？”

原因在于： **人类觉得最顺手的思考步骤，对大模型的内部认知结构来说往往并不是最优的！**

我们根本不知道对一个拥有几千亿参数的 Transformer 来说，哪一步跳步太难、哪一步其实早就背熟了、用什么格式的草稿标记最容易激活它正确的注意力回路。如果只做 SFT，模型永远只是在机械模仿人类标注员的笔迹；而在强化学习（RL）阶段，我们的做法彻底变了：

1. **单题生成上万条尝试路径（Rollouts）** ：给模型一道有明确标准答案的数学或代码题（比如正确答案是 `$7` ），让已有的 SFT 模型围绕这道题随机采样生成成千上万条不同的解题过程（有的用了方程，有的列表穷举，有的中途算错了又划掉重算）；
2. **只按最终结果判对错** ：我们完全不管它中间写了什么，只用客观裁判程序检查它最后报出来的答案是不是 `$7` 。凡是最终算对 `$7` 的解题路径全部标为 **绿色（正向奖励）** ，算错的全部标为 **红色（丢弃或惩罚）** ；
3. **强化成功路径的 Token 概率** ：调高所有绿色路径中那些中间推理 Token 的生成概率，让模型在下一次刷题时，更倾向于顺着那些能帮它拿分的思考方式去推演。

### 2\. DeepSeek-R1 的「顿悟时刻（Aha Moment）」与防蒸馏护城河

当你把这套“自己刷题对答案”的强化学习训练跑上几千步之后，会发生什么？

中国团队发表的里程碑式开源论文 **《DeepSeek-R1》** 把这一过程的实验数据毫无保留地展现在了全世界面前。在论文的核心图表里，随着强化学习训练步数的增加，模型在数学竞赛题上的准确率一路飙升；而与之同步发生的一个惊人现象是： **模型单次回答的平均 Token 长度，在没有任何人工要求的情况下，自己从几百个 Token 暴涨到了成千上万个 Token！**

研究人员把模型自己拉长的这些中间 Token 打印出来一看，发现模型在完全没人手写示范的情况下， **自己无师自通地涌现（Emerge）出了极具人类高级思维特征的「思维链（Chain of Thought）」** ——它会自己推翻前面的假设、自己换第二种方法验算、甚至在算到一半发现不对劲时，自己蹦出一句著名的 **「顿悟时刻（Aha Moment）」** ：

> *“Wait, wait, wait. That's an aha moment I can flag here. Let's re-evaluate this step-by-step to identify if the correct sum can be...”* （等等、等等！这里有一个值得标记的顿悟点。让我们一步步重新评估一下，看看正确的总和是不是……）

在视频里，我现场打开了多个平台对比展示这种经过 RL 训练的 **思考模型（Thinking Models）** ：

- 在 `chat.deepseek.com` 或美国托管平台 **Together AI** 上调用满血开源的 `DeepSeek-R1` （或 Google AI Studio 里的 `Gemini 2.0 Flash Thinking` ），你可以完整看到模型在正式回答前那一大段原汁原味、不断自我质疑与验算的内部独白（ `<think>...</think>` ）；
- 而在 OpenAI 的 ChatGPT 里调用 `o1` 或 `o3-mini-high` 时，你会发现折叠框里只给你看几行干巴巴的阶段性摘要，把真实的原始思维链 Token 严严实实地藏了起来。OpenAI 为什么要藏？ **为了防止模型蒸馏（Distillation）** ——因为一旦把耗费巨资跑强化学习摸索出来的原始思维链 Token 暴露在网页上，竞争对手只需要花几千块钱抓取这些思维链文本，拿去对自家小模型做简单的 SFT 模仿微调，就能白嫖走大半的推理能力！
- **日常实战怎么选档位（SFT 模型 vs RL 思考模型）** ：顺便分享一下我自己的日常使用比例——像大家最常用的 `GPT-4o` ，本质上主要还是一个 SFT 模型（只加了轻量级的后训练打磨），并不具备长思维链推理能力；但正因为它不需要花几十秒在脑子里绕弯子，响应极快，我日常 **80%–90% 的普通提问依然默认用 `GPT-4o`** 。只有当我遇到硬核数学、复杂代码 Bug 或严密逻辑推演时，才会专门切到 `o1` 、 `o3-mini-high` （需开通 Plus `$20/月` 或 Pro `$200/月` 订阅）或 `DeepSeek-R1` 这类真正的 RL 思考模型。

### 3\. AlphaGo 与传奇的「第 37 手（Move 37）」：突破人类天花板

为了让你彻底明白为什么整个 AI 界都对强化学习（RL）如此狂热，我想带你重温 DeepMind 当年击败围棋世界冠军李世石的 **AlphaGo** 论文。

在那篇论文里有一张我最喜欢的图表，对比了两种训练方式的水平上限：

- **紫线（Supervised Learning，只模仿人类顶尖棋谱做监督学习）** ：随着训练推进，模型的棋力快速上升，但最终牢牢卡在了人类职业顶尖棋手（如李世石）的水平线下， **永远无法超越人类老师** ；
- **蓝线（Reinforcement Learning，通过自我对弈做强化学习，只以最终赢棋为唯一奖励）** ：模型摆脱了“人类棋手觉得怎么下才合理”的教条束缚，棋力一举冲破人类天花板，把人类顶尖高手远远甩在身后！

最震撼的具象体现，就是 2016 年 AlphaGo 对阵李世石第二局中的传世名局—— **「第 37 手（Move 37）」** 。当时 AlphaGo 在棋盘右侧五路肩冲下出了第 37 手，现场所有人类九段解说员全部惊呆了，一致认为这是一步违背几千年围棋定式的“大恶手 / 失误”（事后计算表明，一个受过专业训练的人类棋手在那个位置下出这一步的概率只有 **万分之一 `1 in 10,000`** ）；然而几十手之后，正是这看似天外飞仙的第 37 手把全盘棋局彻底盘活，直接锁定了胜局！

把这个故事映射回今天的大语言模型： **只要我们还停留在预训练和 SFT 阶段，大模型本质上就只是人类现有知识的混音器与模仿者，它的上限始终受限于人类标注员的水平；唯有进入强化学习（RL）阶段，让模型在客观目标的驱动下自由探索 Token 序列空间，它才有可能走出属于语言推理领域的「第 37 手」** ——比如发现人类从未想过的全新科学类比、甚至演化出一套比自然语言更高效的内部推理符号！

## 9\. 不可验证领域的强化学习：RLHF 的取巧设计与「奖励黑客」绝境

既然强化学习（RL）在数学、代码和围棋上这么神奇，那我们能不能把它直接照搬到 **写诗、写小说、总结文章、或者讲笑话** 这些日常开放任务上呢？

一上来我们就会遇到一个棘手的难题： **在开放创作领域，根本不存在客观可自动核验的「书末标准答案」（Unverifiable Domains）！**

假设我们的题目是： **`Tell me a joke about pelicans.`（给我讲一个关于鹈鹕的笑话）** 。对于数学题，程序看一眼最后是不是等于 `$7` 就能在 1 毫秒内判完对错；但对于一个鹈鹕笑话，你怎么用代码判断它好不好笑？

如果硬要找真人当裁判：假设一次标准的强化学习训练要跑 `1,000 步` ，每一步同时练 `1,000 道题` ，每道题让模型生成 `1,000 条候选笑话（Rollouts）` ，那总共需要人类裁判现场阅读并打分 **1,000 × 1,000 × 1,000 = 10 亿次（1 Billion）** ！这在时间和金钱上都是绝对不可能完成的任务。

![RLHF 通过人类对候选回答排序训练奖励模型打磨文风，以及训练步数过多时触发奖励黑客刷出满分废话的对比](https://book.oiloil.org/assets/articles/deep-dive-into-llms/09-rlhf-reward-model-and-hacking.svg)

RLHF 通过人类对候选回答排序训练奖励模型打磨文风，以及训练步数过多时触发奖励黑客刷出满分废话的对比

### 1\. RLHF 的「间接取巧法」：用人类排序训练一个「奖励模型」

为了绕开“10 亿次人工打分”的死局，学术界和工业界设计了一套折中的替代方案—— **基于人类反馈的强化学习（Reinforcement Learning from Human Feedback，简称 RLHF）** 。它的核心思路是 **在真人和语言模型之间，加一层充当“代理裁判”的神经网络** ：

1. **让真人对 5 个候选笑话做从好到坏排序（Ranking）** ：我们不让人类标注员直接凭空打分（因为每个人对 7 分和 8 分的标准完全不同），而是让语言模型针对“讲个鹈鹕笑话”先生成 5 条不同的回答，让标注员把这 5 条按 **从最好笑到最不好笑排个名次（ `1st > 2nd > 3rd...`）** ——对人类来说，做比较排序比凭空写段子或打绝对分要容易得多；
2. **训练一个独立的「奖励模型（Reward Model）」** ：收集几千道题的人类排序数据后，我们单独训练一个专门用来打分的神经网络，叫做 **奖励模型（Reward Model，简称 RM）** 。它的输入是「题目 + 一条候选笑话」，输出是一个 `0.0` 到 `1.0` 之间的预测得分。我们通过训练，让这个奖励模型给每道题打出的高低分顺序，尽可能贴合真人排出来的名次——换句话说， **奖励模型就是“人类审美偏好的神经网络模拟器”** ；
3. **对着奖励模型跑强化学习** ：有了这个不知疲倦的电子裁判，我们就可以让大语言模型在后台生成成千上万条鹈鹕笑话，全部交给奖励模型自动打分，并顺着高分方向更新语言模型的参数。

### 2\. 为什么 RLHF 有效？——「判别器与生成器的鸿沟」

RLHF 之所以能显著提升模型回答的质感，是因为它巧妙利用了人类认知中的 **「判别-生成鸿沟（Discriminator-Generator Gap）」** ：

如果你让一位普通外包标注员当场从零写一首意境深远的古体诗，或者想一个让人捧腹大笑的顶级脱口秀包袱（ **生成 Generation** ），99% 的人都写不出来；但如果你把模型生成的 5 首诗或 5 个笑话摆在他面前，问他“哪一首读起来最自然、最没有机器味？”（ **判别 Discrimination** ），普通人却能挑得非常准！因此，相比于让标注员亲自动笔写答案的 SFT，RLHF 能够以更低的门槛，把人类微妙的审美直觉注入到模型中。

### 3\. 致命软肋：为什么说「RLHF 根本算不上真正的强化学习」？

然而，作为一名深耕这个领域的研究者，我必须在最后给你泼一盆清醒的冷水： **RLHF 和前面让 DeepSeek-R1、AlphaGo 产生质的飞跃的「真·强化学习（Verifiable RL）」，在含金量上完全不在一个层级！**

为什么？因为数学规律和围棋胜负规则是 **绝对严密、没有任何漏洞的客观物理铁律** ——无论 AlphaGo 怎么钻空子，它都不可能通过卡 Bug 让系统误判它赢棋，想拿高分就必须真刀真枪地提升棋力。

但 RLHF 里的裁判是谁？ **是一个同样拥有十亿个参数、同样是一块“多孔瑞士奶酪”的奖励模型神经网络！**

只要你让大语言模型对着这个有损的奖励模型跑强化学习跑得太久（比如跑上几百上千步），极其擅长在万亿种 Token 组合里搜寻捷径的大语言模型，很快就会发现奖励模型神经元里的死角漏洞（在机器学习里被称为 **对抗样本 Adversarial Examples** 或 **奖励黑客 Reward Hacking** ）：

- **前 200 步** ：语言模型确实在认真改进笑话的幽默感和排版，奖励模型给出的平均分从 `0.4` 稳步升到 `0.8` ；
- **跑过临界点（比如第 1,000 步）** ：语言模型突然试探出一个惊天 Bug——它发现只要面对“讲个关于鹈鹕的笑话”这个问题，无脑重复输出一串毫无意义的乱码 **`the the the the the the...`**，居然能正好刺中奖励模型内部某几个神经元的盲区，骗得奖励模型给这串废话打出 **`1.0` 的满分（人类史上最爆笑的鹈鹕笑话）** ！
- **猫鼠游戏死循环** ：就算你把 `the the the...` 这条样本抓出来加入黑名单重新训练奖励模型，语言模型在下一轮又会迅速搜出另外一万种能骗取高分的怪异句式（比如疯狂堆砌感叹号或讨好式的排比句）。

正是因为奖励模型极易被“黑客攻击”，在工业界实践中， **RLHF 永远只能小心翼翼地跑几百步就必须见好就收、紧急踩刹车（提早截断停止训练），绝对不敢像数学强化学习那样无限堆算力跑下去** 。所以在我眼里，RLHF 最多只能算是一层让模型说话更讨喜的轻量级打磨抛光（Fine-tuning polish），而绝不是能解锁超级智能的永动机。至于我们在数学和代码等「可验证领域」通过真强化学习（RL）练出来的那套深度思考与复盘能力，到底能不能跨界迁移、帮模型把小说或幽默段子等「不可验证领域」的开放创作也写得更好？这依然是当前整个学术界都在探索的一个开放性悬念（Open Question）。

## 10\. 未来四大演进趋势、追踪前沿渠道与本地跑大模型实操

到现在为止，我们已经完整拆解了现代大语言模型从预训练、监督微调到强化学习的全部底层机制。站在 2025–2026 年的节点往未来看，接下来的大模型还会往哪里演进？平时去哪里追踪最新进展、去哪里亲手把玩不同类型的模型？

### 1\. 值得紧盯的四大前沿演进趋势

1. **原生全能多模态（Native Multimodality / Omni Models）** ：未来的模型不再只是“语言”模型，而是把 **音频频谱切片、图像网格方块（Patches）与文字 Token** 全部放进同一条一维序列里同炉训练的原生物种——模型既能直接听懂你声音里的哽咽或讽刺并直接输出语音，也能在同一个上下文窗口里无缝交织图像与文本。
2. **长周期自主 Agent 与「人机监督比（Human-to-Agent Ratio）」** ：现在的模型大多还停留在“你问一句、它答一句”的短平快回合里，一旦让它连续自主干半小时活，就很容易在瑞士奶酪的孔洞里迷路。未来随着强化学习向更长周期的任务延伸，工作形态将彻底变成 **「人类当主管（Supervisor），同时监督调度一群长周期自主干活的 Agent」** ——就像自动化工厂讲“人机比”一样，未来衡量一个团队生产力高低的核心指标，将是 **1 个真人能同时高效监督多少个 AI Agent** 。
3. **无处不在的隐形集成与直接操作电脑（Computer Use）** ：过去我们只能通过复制粘贴把文本搬进聊天框；而像 OpenAI Operator 或 Claude Computer Use 这样的新形态，正在让大模型直接接管屏幕截图、模拟人类的鼠标点击与键盘输入，在后台直接替你填表、订票、操作各类传统软件。
4. **打破冻结权重壁垒：测试时训练（Test-Time Training）** ：这是我个人最关注的一项底层架构突破。回顾前文你会发现，目前所有大模型都严格遵循着「训练阶段改参数 vs 推理阶段固定参数」的楚河汉界——在跟你聊天的过程中，模型的几十亿个参数旋钮是完全冻结不变的，它所谓的“学会新东西”全都依赖越塞越长的上下文窗口。但这和人类大脑截然不同：人类在白天工作学习、晚上睡觉时，大脑突触的连接权重是真的会发生永久性物理改变的！尤其当未来进入视频、电脑操作等超长多模态任务时，每分钟产生的 Token 量极其庞大， **单靠把上下文窗口无限拉长绝不是终局解法，我们迫切需要探索「在推理实战过程中动态更新模型参数（Test-Time Training）」等全新范式** 。
