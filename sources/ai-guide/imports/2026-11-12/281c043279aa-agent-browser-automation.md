## 前言

哈喽大家好，我是欧呦，这篇文章将为大家分享 AI Agent 的浏览器自动化与电脑自动化指南。在这篇文章里，我们会先聊聊 AI 自动化相比传统脚本的核心优势，再按操作便捷度与 Token 开销梳理出三级自动化方式的优先级，接着拆解浏览器自动化与电脑自动化的高频使用场景及提示词写法，最后带大家一步步配好 Ego Lite、Chrome 插件和桌面控制工具。

在 AI Agent 出现之前，如果我们想让电脑自动帮我们操作网页或者软件——比如定时抓一批数据、批量填几十张表单——通常只有两条路：要么自己写爬虫和自动化测试脚本（比如用 Python 配合 Selenium、Playwright），要么去配置传统的 RPA（机器人流程自动化）软件。

用过传统自动化工具的朋友都知道，那套方式的门槛和维护成本非常高：

- **规则全部写死，页面一改就崩** ：你必须提前打开网页源码，手动找到每个按钮的代码路径，把「第一步点哪里、第二步填什么」一行行写死。只要目标网站稍微改个版、换个按钮位置，或者中途突然弹出一个活动弹窗，脚本就会立刻报错卡死，往往修脚本的时间比自己手动点完还要长。
- **只能机械执行，看不懂页面内容** ：传统脚本只是一个没有脑子的点击机器。它只能机械地把第 A 格的字复制到第 B 格，没法一边看网页内容一边做判断——比如你没法让传统脚本「去闲鱼挑几台性价比最高、看起来不是商家的二手电脑」，因为它根本读不懂商品描述。

而到了 AI Agent 时代，自动化的底层逻辑彻底变了。现在的 AI 自动化不再需要你手写死板的规则，而是直接把大模型的理解能力接进了浏览器和电脑桌面，带来了三个非常明显的优势：

1. **自然语言直接驱动，不用写一行选择器代码** ：你不需要再去扒网页源码找按钮编号，直接像跟人说话一样告诉它「帮我把这份发票报销了」或者「帮我把视频传到这几个平台存成草稿」，AI 自己会看界面找入口。
2. **页面改版或弹出提示时能随机应变** ：因为 AI 每一步都能看懂当前的界面结构或屏幕画面，哪怕网页改了排版、或者中途跳出一个更新提示框，它也能自己把弹窗关掉，找到正确的按钮继续往下走。
3. **「动手操作」与「动脑判断」合二为一** ：AI 在帮你翻页、点击的同时，还能实时读懂页面上的图文信息并做出决策——比如一边翻电商评论区一边提炼差评痛点，或者一边点击测试你刚写的网页、一边顺手把报错的 Bug 修好。

## 自动化方式的优先级

搞清楚了 AI 自动化的优势之后，当我们真正想让 AI Agent 替我们去操作外部网站或软件时，首先要建立一个清晰的判断标准：面对一个任务，到底该选哪种方式让 AI 去执行？

### 1\. 三级自动化方式排序

在我自己的工作流里，判断用哪种自动化方式，完全取决于 **AI Agent 操作它的便捷程度** 以及 **Token 开销** （Token 是大模型读写文字与图片时的计费和容量单位）。按照这两个维度，我把所有自动化方式排成了三个优先级：

![按操作便捷度与 Token 开销划分的三级自动化优先级](https://book.oiloil.org/assets/articles/agent-browser-automation/01-automation-priority-tiers-v1.svg)

按操作便捷度与 Token 开销划分的三级自动化优先级

#### 第一优先级：API 与 CLI（命令行工具）

如果我们要操作的目标服务提供了现成的 **API** （程序之间直接收发数据的接口）或者 **CLI** （在电脑终端里敲一行文字指令就能调用的工具，比如飞书 CLI、GitHub CLI），那么 **API 和 CLI 永远是第一选择** 。

因为对 AI Agent 来说，敲一行命令、拿回一段纯文字或结构化数据（JSON），操作是最直接、最简单的，传入和返回的上下文也最精简，既快又省 Token。

#### 第二优先级：浏览器自动化（Browser Use）

如果目标服务没有提供 API 或 CLI（比如绝大多数外部网站和公司内部后台），只要它是一个 **能在浏览器里打开的网页** ，我们就优先使用 **浏览器自动化** 。

通过浏览器自动化，AI Agent 可以直接控制浏览器打开网页、读取页面文字、点击按钮、填写输入框和上传文件，帮我们把网页端原本需要人工点击的流程自动跑完。

#### 第三优先级（最后兜底）：电脑自动化（Computer Use）

如果我们要操作的是一个 **桌面端软件** ，它既没有提供外部的 API 或 CLI 可以访问，也没法在浏览器里打开网页版，那我们最后兜底的方案才是 **电脑自动化（Computer Use）** 。

它会像真人坐在电脑前一样，直接看整个电脑屏幕的画面，通过移动鼠标指针和敲击键盘去操控桌面软件。

### 2\. 网页结构与桌面截屏的差异

很多刚开始接触自动化的朋友会有个疑问：既然 Computer Use 可以控制整台电脑上的任何软件，那为什么不干脆所有任务都用它，还要专门分出「浏览器自动化」？

这背后的原因，在于两者理解界面和执行操作的底层原理有着本质差别：

![浏览器自动化直读网页结构与传统电脑自动化截屏猜坐标的原理对比](https://book.oiloil.org/assets/articles/agent-browser-automation/02-dom-vs-pixel-guessing-v1.svg)

浏览器自动化直读网页结构与传统电脑自动化截屏猜坐标的原理对比

#### 感知方式不同：直接读网页结构 vs 截全屏图猜像素坐标

任何一个网页的底下，都有一套现成的代码结构（也就是前端常说的 DOM 树）。页面上的每一个按钮、每一个输入框，在代码里都有明确的名字、标签和层级位置。浏览器自动化工具可以直接读取这份结构清单，精准地告诉浏览器「点击编号为 3 的提交按钮」，不仅指哪打哪、速度极快，而且每次交互只传递很少的文字信息，Token 消耗非常低。

而大多数独立的桌面端软件，并不会对外暴露统一的内部代码结构。传统的 Computer Use 想要操作它们，只能靠 **「每走一步截一张全屏高清图片 → 把图片发给视觉大模型 → 让模型用肉眼估算目标按钮在屏幕上的 `(x, y)` 像素坐标 → 再移动鼠标过去点击」** 。每点一下按钮都要上传一张大图重新推理，不仅执行速度慢、Token 消耗高，遇到屏幕分辨率缩放或者密集的小图标时，还很容易点偏。

#### 运行干扰不同：后台独立运行 vs 抢占物理鼠标与窗口焦点

浏览器自动化可以在专门隔离的工作空间或者后台标签页里自己跑，它在浏览器里翻页、填表的时候，你完全可以同时在电脑上写文档、回消息，两边互不耽误。

但模拟真实鼠标点击的 Computer Use，调用的是电脑系统上唯一的物理鼠标指针，而且必须把目标桌面软件切到屏幕最前面。它在干活的时候，你的手一旦去碰鼠标或者切到别的窗口，就会直接打断它的操作。这也是为什么但凡能在网页里解决的事情，我们都优先交给浏览器自动化。

## 浏览器自动化的场景

明确了优先级之后，我们先来看看日常工作和生活里用得最多的 **浏览器自动化** 。不管你是做开发、做产品运营、做自媒体，还是处理日常个人事务，都可以用它省下大量重复点击的时间。

### 1\. 调研比价与跨系统填表

浏览器自动化最直接的价值，就是 **它可以直接使用我们自己浏览器里已经登录好的账号状态（登录态）** ，去访问那些需要登录才能看的页面，或者在不同网页之间帮我们自动搬运数据。

![浏览器自动化在带登录态调研、电商比价选品与跨系统填表报销中的应用](https://book.oiloil.org/assets/articles/agent-browser-automation/03-browser-research-and-forms-v1.svg)

浏览器自动化在带登录态调研、电商比价选品与跨系统填表报销中的应用

#### 带登录态的联网调研与社媒数据抓取

虽然现在的 AI Agent 大多自带联网搜索工具，能直接查公开的网页新闻，但遇到需要登录账号、或者反爬虫严格的社交与内容平台时，普通联网工具就拿不到完整内容了。

使用浏览器自动化时，AI 可以直接借用你浏览器里现成的登录状态，去深度调研 X（Twitter）、Reddit、GitHub 上的最新讨论；更实用的是，它可以帮你自动打开小红书、视频号、B 站、抖音等平台，抓取某个领域的爆款内容数据，或者直接进你自己的创作者中心拉取近期作品的播放量与互动数据做复盘。平时可以直接这样跟 Agent 说：

用浏览器打开我的小红书创作者中心，拉取最近 10 篇笔记的曝光、观看和点赞数据，帮我分析哪几篇完播和互动最好，整理成 Markdown 表格。

#### 电商选品、评论区痛点挖掘与生活比价

如果你平时做产品调研、电商选品，或者在日常生活里想买大件商品、做旅游攻略，浏览器自动化也是一个很好用的帮手。

比如你可以让它自动去电商平台翻看某类商品的「最新差评」，汇总真实用户的抱怨点；做旅游攻略时，让它结合你登录的小红书避坑帖和酒店预订网站进行跨平台比价。我自己之前换设备的时候，就专门用浏览器自动化跑去闲鱼上面，按照我设定的配置要求和预算区间，自动搜索并筛选出了几台性价比最合适的二手电脑。你可以这样给它下指令：

用浏览器去闲鱼搜索「Mac mini M4 16G」，预算 3200 元以内，帮我排除批量出货的商家号，挑出 5 台个人卖家、描述清楚且性价比最高的机器，把链接和价格列出来。

#### 跨网站机械填表与日常发票报销

在日常办公里，很多公司内部的 OA 审批系统、ERP 后台、财务报销页面或者外部申报网站，往往没有对外开放 API。以前我们只能打开本地表格，一行一行复制粘贴到网页输入框里。

现在你可以直接把整理好的本地发票文件或 Markdown 表格丢给 AI Agent，让它控制浏览器自己打开报销系统，自动填写金额、发票抬头、上传对应的 PDF 附件并提交报销单，把这类枯燥的机械填表工作彻底交给 AI。涉及到提交审批或财务操作时，建议在提示词末尾加上一句「停在提交前等我确认」：

读取当前文件夹 invoices/ 目录下的所有 PDF 发票，用浏览器打开我已登录的公司报销系统页面，依次填入发票金额、开票日期并上传对应 PDF，全部填好后停在提交按钮前等我确认。

### 2\. 云后台配置、发作品与自测

除了查资料和填表单，当你自己在做内容创作或者用 Vibe Coding 开发作品时，浏览器自动化还能直接接管发布与测试环节。

![浏览器自动化在第三方云后台配置、多平台视频分发与前端自动测试中的应用](https://book.oiloil.org/assets/articles/agent-browser-automation/04-browser-publish-and-debug-v1.svg)

浏览器自动化在第三方云后台配置、多平台视频分发与前端自动测试中的应用

#### 替你在复杂的第三方云后台「点按钮配环境」

很多朋友在做独立网站或小产品时，最头疼的就是去 Cloudflare 配域名解析、去 Stripe 配收款 Webhook、或者去飞书开放平台勾选几十个应用权限。面对满屏陌生的英文后台菜单，人对着教程一步步找很容易点错。

有了浏览器自动化之后，你只需要自己在浏览器里登录好对应的平台，然后把官方文档链接甩给 AI Agent，让它直接在浏览器里替你点进后台菜单、打开对应的开关、填好回调地址，再把生成的密钥复制回本地项目里：

参考这篇官方文档链接，用浏览器在我已经登录的 Cloudflare 后台里，帮我把域名配好 DNS 解析指到 Vercel 上，并开启 HTTPS 自动跳转。

#### 多平台视频与内容自动发布

如果你平时做自媒体，一篇文章或一期视频做完后，往往要同时发到小红书、抖音、B 站、视频号和 YouTube 五六个平台。每个平台都要单独打开网页、上传视频、填标题、敲标签、传封面，重复操作非常费时间。

我自己平时就把这套多平台发稿流程封装成了一个叫 `video-publisher` 的 Skill：当我准备好本地视频、标题和封面后，触发这个 Skill，AI Agent 就会通过浏览器自动化一次性打开各个平台的创作者后台，自动把视频传上去、填好标题和标签，并全部保存为已验证的发布草稿，最后我只需要点一下最终发布按钮就行。哪怕不写专门的 Skill，你平时也可以直接这样交代它：

用浏览器分别打开小红书、抖音和 B 站的创作者中心上传页面，把当前目录下的 demo.mp4 上传上去，标题填「3 分钟搞懂浏览器自动化」，填好标签后全部存为草稿，不要直接点发布。

#### Vibe Coding 自动调试 Bug 与前端自动化测试

我们在用 Vibe Coding 写网页或前端应用时，如果每改完一处代码都要自己切到浏览器去点一遍按钮、看控制台有没有报错，再来回截图发给 AI，效率会很低。

配好浏览器自动化后，AI Agent 写完代码就会自己打开本地预览网页，自己点击页面上的交互按钮、填写测试表单、检查页面排版和控制台报错信息。发现 Bug 它会自己顺手改掉再测一遍，跑完一整套自动化测试后再把干净的结果交给你：

启动本地预览服务，用浏览器打开 localhost:3000，把页面上所有的按钮和弹窗都点一遍，检查排版有没有错位、控制台有没有报错；如果有报错就直接帮我修好代码再测一遍。

## 浏览器自动化工具与配置

目前市面上做浏览器自动化的工具不少，比如早期的 `Agent Browser` 、前端测试工具 `Playwright` ，或者需要手动配置连接协议的 `Browser MCP` 。但实际用下来，早期那些工具要么需要单独启动一个没有登录态的空白浏览器（每次都要重新扫码登录各个平台，甚至把你原本主浏览器的账号挤下线），要么配置连接非常繁琐。

结合易用性、复用登录态的顺滑度以及执行速度，我现在最推荐两套方案： **首选 Ego Lite，次选 AI Agent 自带的 Chrome 插件** 。

### 1\. 首选方案：Ego Lite 浏览器

在所有浏览器自动化工具里，我目前把 **[Ego Lite](https://lite.ego.app/)** （也叫 Ego Browser）放在第一推荐。它本身是一个专门面向 AI Agent 设计的桌面浏览器产品，核心解决了传统工具最让人头疼的两个问题：

![Ego Lite 的 Space 独立空间隔离与 Node.js 脚本批量执行优势](https://book.oiloil.org/assets/articles/agent-browser-automation/05-ego-lite-space-and-script-v1.svg)

Ego Lite 的 Space 独立空间隔离与 Node.js 脚本批量执行优势

#### 优势一：提供 Space（独立工作空间），不乱开标签页打扰人

以前用插件或普通自动化工具控制浏览器时，AI 会在你正在使用的浏览器窗口里直接新建一大堆标签页或者标签组；如果两个任务同时跑，一个任务切换页面或卡死，还会直接影响另一个任务。

Ego Lite 在浏览器内部设计了 **Space（工作空间）** 的概念。它允许人和 AI Agent 一起在同一个浏览器产品里工作，既能共享你从 Chrome 同步过来的账号登录态，又让 **人和每个 AI 任务各自待在独立的 Space 里** ——AI 在它的专属 Space 里打开网页、翻页和点击，完全不会在你眼前正在看的浏览器主界面里乱弹标签页，多个 AI 任务并行跑的时候也互不干扰。

#### 优势二：内置 Node.js 环境与封装函数，多步合并成脚本一次跑完

传统的浏览器自动化工具（包括普通插件和早期的 CLI 工具），执行方式都是「一步一命令」：AI 先发一条命令读取页面元素，判断点哪里，点完再发一条命令看页面反馈，比如发个视频要填标题、点原创开关、加标签，得来回交互好几轮，步骤又碎又慢，Token 消耗也高。

而 Ego Lite 内置了自己的 **Node.js 运行环境** 和一整套封装好的全局操作函数。AI 看完页面结构之后，可以把后面的连续多步操作（比如上传文件、填标题、勾开关，以及条件判断与报错自动重试）直接写成一段脚本 **合并执行一次** 。把零碎的多轮问答合并成一次脚本运行后，它的执行速度比传统工具快得多。

#### Ego Lite 的配置与上手四步法

1. **下载安装并一键同步 Chrome 数据** ：打开 Ego Lite 官网（ [lite.ego.app](https://lite.ego.app/) ）下载安装包。第一次打开软件时，按照新手引导点击同步按钮，它会把你原本 Chrome 浏览器里的登录态、书签和历史记录一键同步过来，不需要重新登录各个网站。
2. **自动挂载全局 Skill** ：完成初始化后，Ego Lite 会自动把配套的 `ego-browser` Skill 安装到你电脑上的 Codex、Claude Code 等主流 AI Agent 里，不需要你再去手动敲命令行安装（如果安装时你的 Agent 客户端正开着，重启一下客户端就能刷出来）。
3. **在 Agent 中直接调用** ：打开任何一个 AI Agent，既可以在输入框按 `/` 选择 `ego-browser` 触发 Skill，也可以直接用自然语言告诉它用 Ego 浏览器完成任务（比如「帮我打开小红书创作者中心复盘一下最近 5 篇笔记的数据」）。
4. **随时查看进度与人工接管** ：任务开始后，浏览器右上角会出现一个小鼠标图标，旁边的数字代表后台有几个 Agent 正在干活。点开图标切进 Agent 的 Space 就能看到实时操作画面；如果中途遇到滑块验证码或必须扫码确认的环节，直接点击底部的 **「接管」** 按钮手动处理完，再交还给 AI 继续跑即可。

### 2\. 次选方案：Agent 自带插件

如果你实在不想在电脑上多装一个浏览器，只希望直接控制手头正在用的 Chrome 浏览器，那么次选方案是使用 **AI Agent 官方自带的 Chrome 插件** （虽然在空间隔离和批量脚本执行速度上不如 Ego Lite 方便，但比早期的 `Agent Browser` 和手动配置连接协议省事很多）。

![在 AI Agent 中安装官方 Chrome 插件与浏览器扩展的配置流程](https://book.oiloil.org/assets/articles/agent-browser-automation/06-agent-chrome-extension-v1.svg)

在 AI Agent 中安装官方 Chrome 插件与浏览器扩展的配置流程

以 Codex 官方自带的 `Chrome` 插件为例，配置步骤非常简单：

1. **在客户端安装 Chrome 插件** ：打开 Codex 客户端左侧的 `Plugins` （插件）页面，在列表里搜索并安装官方的 `Chrome` 插件，安装后系统会自动附带一个对应的浏览器控制 Skill。
2. **安装配套的浏览器扩展** ：根据插件安装引导，在你的 Chrome 浏览器里装好对应的扩展程序。安装完成后，在 Chrome 右上角的扩展栏里能看到 Codex 的图标。
3. **直接复用现有 Chrome 登录态** ：接下来在 Codex 里交代网页任务时，它就会通过这个浏览器扩展直接控制你当前的 Chrome 窗口，比如自动新建一个标签页分组去操作你已经登录好的 GitHub、抖音或小红书后台。

## 电脑自动化场景与配置

聊完了网页端的浏览器自动化，我们最后来看负责兜底的 **电脑自动化（Computer Use）** ——也就是当目标软件既没有 API/CLI，也不是网页的时候，怎么让 AI 直接接管桌面软件。

### 1\. 电脑自动化的三类兜底场景

在我自己的日常使用中，只要能用 CLI 或浏览器解决的绝不用电脑自动化；但遇到以下三类场景时，Computer Use 就能帮我们解决以前根本没法自动化的问题：

![电脑自动化在调试微信小程序与桌面软件、无接口软件导出及封闭应用提取中的三类兜底场景](https://book.oiloil.org/assets/articles/agent-browser-automation/07-computer-use-scenarios-v1.svg)

电脑自动化在调试微信小程序与桌面软件、无接口软件导出及封闭应用提取中的三类兜底场景

#### 场景一：调试微信小程序或桌面原生软件

当我们用 Vibe Coding 开发微信小程序，或者开发 Mac / Windows 桌面客户端应用时，程序运行在独立的「微信开发者工具」模拟器或原生桌面窗口里，浏览器自动化工具是进不去的。这时候就可以让 AI 开启电脑自动化，自己去点击小程序模拟器的页面、触发交互并查看界面反馈，完成闭环调试：

帮我操作桌面上打开的「微信开发者工具」模拟器，依次点击底部三个导航栏和顶部的搜索按钮，看看页面跳转正不正常，有没有报错弹窗。

#### 场景二：操作完全没有接口的桌面软件（如剪辑软件自动导出）

很多我们每天都在用的专业桌面软件——比如视频剪辑软件（剪映等）、本地设计工具或传统办公套件，它们既没有对外提供 API 接口，也没有命令行工具。

比如在我的自动剪辑工作流里，前面粗剪、加字幕都可以靠脚本处理，唯独最后一步「从剪映里把工程导出成视频文件」没有任何接口可调。这时候就可以用电脑自动化顶上去：让 AI 自己控制鼠标在剪映界面里点击「导出 → 选择分辨率 → 确认导出」，把整个自动化流真正串通：

切到桌面上打开的剪映窗口，点击右上角的「导出」，把分辨率设为 1080p，导出到当前项目的 output/ 文件夹里。

#### 场景三：提取封闭桌面软件里的信息

像电脑端的微信客户端，既没有开放接口，也没有完整的网页版，数据非常封闭。如果你想把某个微信群或桌面软件里很长的历史聊天记录翻出来、提取里面的干货链接或整理成纪要，靠人一条条往上翻和复制非常折磨，就可以交给电脑自动化挂在那里慢慢翻页提取：

打开电脑上的飞书客户端，找到「AI 产品市集」群，往上翻最近 20 条群聊消息，把大家讨论的核心观点和链接提取出来，整理保存到 notes.md。

### 2\. 开启内置控制与备选方案

现在配置电脑自动化比早期简单了很多。我的建议是： **优先直接使用 AI Agent 客户端自带的第一方 Computer Use；如果你用的工具还没有内置，再使用开源的 `agent-desktop` 方案。**

![在 Codex 的 Settings 页面开启内置的 Computer use 控制开关](https://book.oiloil.org/assets/articles/agent-browser-automation/08-codex-computer-use-settings.webp)

在 Codex 的 Settings 页面开启内置的 Computer use 控制开关

#### 首选：开启 Agent 自带的第一方 Computer Use

现在很多主流的 AI Agent 桌面端都已经原生内置了第一方的 Computer Use 能力，不需要自己去装额外的插件。

如上方界面所示，以 Codex 桌面端为例：

1. 点击客户端左下角进入 **`Settings` （设置）** ，在左侧菜单栏底部的 `Integrations` 分组里找到 **`Computer use`** 。
2. 在右侧的 `Control` 区域，把第一项 **`Any App` （允许控制电脑上的应用）** 右侧的开关打开即可。下面还可以按需配置是否允许锁屏状态下运行（ `Locked use` ），以及管理始终允许直接控制的应用白名单（ `Always-allowed apps` ）。
3. **开启 macOS 必备的两个系统权限并直接调用** ：第一次让 Agent 控制电脑时，系统会弹出授权提示。我们需要在 macOS 的「系统设置 → 隐私与安全性」里，给对应的 Agent 客户端开启 **「辅助功能」** （对应模拟鼠标点击和键盘输入）和 **「屏幕录制」** （对应截取屏幕画面看清界面）这两个开关。配好之后回到聊天框，直接用自然语言告诉它要操作哪个桌面软件（比如「帮我控制剪映把当前工程导出成 1080p 视频」），Agent 就会自动接管桌面开始执行。

#### 备选：没有第一方支持时使用 vercel-labs/agent-desktop

如果你正在使用的 AI Agent 还没有内置第一方的 Computer Use（或者你想在命令行 Agent 里更省 Token 地操控桌面软件），推荐使用 Vercel 实验室开源的 **[vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)** 。

它的设计思路很巧妙：为了避开传统电脑自动化「反复截大图猜坐标」又慢又费 Token 的毛病，它直接调用操作系统自带的 **无障碍树接口（Accessibility Tree）** ——也就是系统专门给读屏辅助软件提供的界面结构清单，把桌面软件窗口里的按钮、输入框全部转换成带编号（ `ref` ）的结构化数据。

最省事的配置方式，是直接把它的开源仓库链接（ `https://github.com/vercel-labs/agent-desktop` ）发给你的 AI Agent，让 Agent 照着仓库说明帮你把命令行工具（ `npm i -g agent-desktop` ）和配套的 Skill 装好：

```
npm i -g agent-desktop
npx skills add vercel-labs/agent-desktop
```

安装完成后，任何支持执行终端命令的 AI Agent 都可以像操作网页结构一样，直接按元素编号精准点击桌面软件里的按钮，甚至直接在后台触发点击而不抢占你的物理鼠标。

#### 实操避坑提醒：注意鼠标焦点冲突

最后提醒大家一个实操细节：当你使用像 **Codex 内置 Computer Use** 这类基于「屏幕截图 + 模拟真实鼠标点击」的方案跑任务时， **在 AI 执行操作的过程中，我们自己的手千万不要去动鼠标，也不要随便切换桌面窗口** 。

因为一旦你动了鼠标或者把别的软件切到前台，AI 下一秒点下去的位置就会完全错位。对于需要翻很多页聊天记录或者批量导出工程这类耗时较长的电脑自动化任务，建议趁你离开工位休息、出门吃饭的时候让它跑，或者干脆把它部署在家里一台闲置的备用电脑（比如 Mac mini）上专门替你干活。

## 总结

最后，我们把整篇文章最核心的判断标准与配置脉络总结成三点，方便大家在实际工作流里随时对照：

1. **按「操作便捷度 + Token 开销」决定自动化优先级** ：遇到外部任务时，先看目标服务有没有提供现成的 **API 或 CLI** （最快、最省 Token）；如果没有，只要能在网页里打开，就优先用 **浏览器自动化** （直接读取网页结构树，后台运行不抢鼠标）；只有面对既无接口也没网页版的桌面端软件，才用 **电脑自动化（Computer Use）** 做最后兜底。
2. **浏览器自动化首选 Ego Lite，次选自带 Chrome 插件** ：平时做带登录态的社媒调研、闲鱼比价选品、自动填表报销、配第三方云后台、多平台发视频草稿或前端自测时，推荐首选 **[Ego Lite](https://lite.ego.app/)** ，既能同步 Chrome 登录态，又能靠独立的 `Space` 避免乱弹标签页，还能用内置的 `Node.js` 环境把多步操作合并成脚本一次跑完；如果不想多装浏览器，则直接在 Agent 的 `Plugins` 里安装官方自带的 `Chrome` 插件。
3. **电脑自动化优先开启客户端内置能力，备选 `agent-desktop`** ：调试微信小程序、让剪映自动点导出或提取封闭桌面端群聊时，优先在 Codex 等客户端的 `Settings → Integrations → Computer use` 里开启 `Any App` ，并在 macOS 系统设置里打开「辅助功能」和「屏幕录制」权限；如果手头的 Agent 没有内置第一方桌面控制，就安装开源的 **[vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)** ，通过系统无障碍树在后台精准点击桌面软件元素。

把这套浏览器自动化与电脑自动化工具配好之后，你的 AI Agent 就不再局限于本地的项目文件夹，而是真正能替你在各个网站和桌面软件之间跑通完整的日常工作流了。
