## 为什么做商业化付费 Skill

很多人知道 Skill 的本质就是一个文件夹，里面放着 Markdown 文档和脚本，心里可能会有一个疑问： **这种东西别人一看源码不就学会了吗，凭什么能卖钱？**

![小白让 AI 生成的空泛提示词与沉淀深度工作流和定制脚本的付费 Skill 对比](https://book.oiloil.org/assets/articles/commercial-paid-skill/03-plaintext-skill-value-barrier-v1.svg)

小白让 AI 生成的空泛提示词与沉淀深度工作流和定制脚本的付费 Skill 对比

这个疑问其实很合理。因为 Skill 本质上就算付费交付了，也依然是明文的。即便是市面上很多声称自己有 Skill 加密机制的平台，只要你的 AI Agent 想要去调用这个 Skill，它想要拿到里面所有完整的信息也是非常简单的。

那为什么一个自己用着顺手的好 Skill，和一个别人愿意掏钱买的付费化 Skill 会有区别？核心就在于 **这个 Skill 里面的技术含量，以及它对于实际工作的帮助** 。

这就像现在有很多 Vibe Coding（通过自然语言让 AI 写代码）做出来的产品，但是一些更有技术能力的人写出来的产品，或者更有设计审美的人做出来的产品，它的使用体验就是远高于普通 Vibe Coding 产品的。

写 Skill 其实也是一样。Skill 里面承载的是知识以及工作流程。对于 AI 的理解比较深入的人，他写出来的 Skill 肯定是比一个小白仅依赖 AI 去生成的 Skill 效果更好的——因为他能够准确地捕捉 AI 做得不好的地方，并针对这些问题设计对应的工作流和工具。

## 明文交付为什么有人付费

既然 Skill 交付出去也是明文的，用户之所以还是愿意为这个 Skill 付费，主要有三个原因：

![用户愿意为明文交付的付费 Skill 买单的三大核心支点](https://book.oiloil.org/assets/articles/commercial-paid-skill/04-why-users-pay-three-pillars-v1.svg)

用户愿意为明文交付的付费 Skill 买单的三大核心支点

1. **对于你这个人的信任** ：我平时作为一个自媒体博主，讲的内容也算比较干货，大家会有一些信任感。但是我之前是没有提供给大家消费的产品的，那么当我推出了一个契合我专业方向的产品后，用户就会有一个消费的入口。
2. **Skill 本身确实有用** ：以设计类 Skill 为例，Pro 版本相较于普通版本，在设计流程和洞察上确实存在差异，做出来的效果能够比开源版本更好。对于有这方面实际需求的用户来说，他们就会愿意购买。
3. **相信你的 Skill 会持续更新、持续迭代** ：这是付费 Skill 最主要的一个门槛。复制出去的文件只能停留在当时的版本，而购买正版的用户，买到的是这个产品后续的持续更新与迭代。

## 选择付费方向与建立壁垒

### 1\. 为什么我选择从 UI 设计切入？

我之所以选择 UI 设计这个方向去做付费 Skill（ [Oil UI Pro](https://ui.oiloil.org/pro) ），是因为我自己日常也经常会遇到 AI 做 UI 设计做得不好的问题。

而且我作为一个 AI 的高频使用者，对市面上各种模型都非常了解。那么连我都会遇到很多 UI 设计问题，说明 AI 在这方面确实做得还不够好；同时我在长期使用的过程里，对于怎么解决这些问题也确实有一些自己的洞察。

### 2\. 把洞察落到工作流、评审机制与定位脚本上

有了对 AI 短板的洞察之后，不能只是在文档里多写几句提示词，而是要把它做成更产品化的实现。

在我的设计 Skill 里，主要做了下面这三件事：

#### 第一，增加多风格抽卡的工作流与配套模板脚本

让 AI 做设计，它经常一股脑就把全部页面写完了，最终做出来的效果可能和我们想象的不符。

因此在工作流上，我基于自己的理解，增加了一些让 AI 先设计不同风格的工作流，方便用户抽卡挑选。除了有这个工作流之外，我还提供了对应的模板脚本，这样 AI Agent 可以非常简单地把这些不同风格的模板聚合起来提供给用户查看，不需要每次都消耗很多 Token 去写这个聚合展示页面，这是一个更加产品化的实现。

#### 第二，在 Review 机制上利用子 Agent 进行评分与修复

在 Review（评审）机制上，我利用了子 Agent（由主 Agent 派发、拥有独立上下文的分身）的机制。虽然现在大多数的 Agent 工具里面都有子 Agent 功能，但大家平时在让 AI 做设计的时候，可能不会专门派发一个用于设计评审的子 Agent。

而通过子 Agent 去独立评审的这种机制，对不同的模型来说，评审完一定是会有一部分收益的。它能够严格针对我给它的 Review 标准进行评分，找出并修复页面里的问题，从而进一步提升画面的精致感和设计感。

#### 第三，提供用于真实页面定位的 shoot 脚本

除此以外，我在 Skill 里面还提供了一个用于给 AI Agent 进行真实页面定位的脚本，叫做 `shoot` 。

AI Agent 在实际去检查页面的时候，利用这个脚本就可以非常方便地获取当前设计的一些真实信息（如页面渲染截图与布局诊断数据）。这对于一些能力比较弱的模型来说会很有帮助。

## 免费版与 Pro 版的划分

### 1\. 针对不同使用场景划分免费版与 Pro 版

关于免费开源版和付费 Pro 版本，我是针对具体的使用场景去划分的：

- **开源免费版（ [oil-ui](https://github.com/oil-oil/oil-ui) ）** ：更加注重于 **从 0 到 1 去做一个新项目、或者新功能** 时的一些设计洞察与基础工具。用户只安装开源版，也能完整走通一个新页面的设计流程；完成任务后，只会通过本地标记控制向用户温和提示一次 Pro 版，不会反复打扰。
- **付费 Pro 版（ [Oil UI Pro](https://ui.oiloil.org/pro) ）** ：对于 **存量项目** 来说，它有更加完整的 Review 流程，以及存量项目优化的一些专属洞察（例如区分已有页面是要优化视觉、改交互流程还是加新功能，并做多轮评分迭代）。

在划分两个版本时，防止明显错误的基础底线和共用工具（如对比页生成脚本、基础截图工具）两边都会保留，保证免费版自己也是完整好用的；而更深度的场景方法与多轮评审闭环则放在 Pro 版中。

### 2\. 单一源头维护与避免双版本冲突

由于每次发版都需要同时维护开源版本和付费版本，在工程管理上主要遵循两个理念：

一是 **单一源头维护** 。日常迭代时只在完整版源仓库里修改，不手动去改两个仓库。通过一份公开文件清单和构建脚本，自动从完整版中抽离生成开源版，并在构建时自动检查开源版里的链接是否正常、有没有遗留半截流程，或者不小心把付费版独有的内容放进了开源版。

二是 **处理好免费版与付费版共存时的触发冲突** 。很多用户是先装了免费版，之后再购买安装 Pro 版的。为了避免两个版本同时在电脑上抢同一类任务，一方面在免费版的描述说明（ `description` ）里写明「已安装 Pro 版本时交给 Pro 版本处理」；另一方面在通过命令行工具安装 Pro 版时，自动清理同一 Agent 技能目录下的免费版，并通过软链接让电脑上的多个 Agent 工具共用同一份安装目录。

## 定价策略与鉴权交付闭环

### 1\. 为什么选择「一次性买断」而不是订阅制？

在定价方式上，我之所以选择一次性买断（包含后续版本更新），主要有两个原因：

第一， **如果在 [Stripe](https://stripe.com/) 里面要支持微信或者支付宝支付，是没有办法走订阅制的** 。作为个人开发者，如果你想要直接去接国内正规的微信、支付宝官方支付接口，是需要有企业商家资质的，不能以个人的名义去注册；而 [Stripe](https://stripe.com/) 个人开发者也可以开通，所以门槛很低，并且可以通过它直接接入微信和支付宝，只是它们在 Stripe 里只支持单次付款、不支持订阅制。如果你缺少了支付宝或者微信支付，转化率会大大降低，尤其是在国内做社媒传播的时候。

第二， **国内用户其实没有很好的订阅付费习惯** 。如果你把按月订阅的价格做低了，大家很有可能订阅了第一个月之后，第二个月就不续费了；并且到了第二个月的时候，你首发内容带来的流量和新增用户其实已经没有第一波那么多了。

所以更合理的做法是：在第一波内容流量好的时候，尽可能地转化更多的用户，并且提高客单价。对应到交付形式上，使用一次性买断制，大家才会更加容易买账。

### 2\. 从开源引流到 CLI 鉴权交付的技术栈与成本

我实际使用的商业化交付链路与技术栈非常轻量，前期固定成本也很低：

- **开源仓库引流到官网** ：我有一个公开的 GitHub 开源仓库 [oil-ui](https://github.com/oil-oil/oil-ui) ，它可以帮我把用户自然转化到我的 Skill 官方网站 [ui.oiloil.org](https://ui.oiloil.org/) 。在这个网站上会展示用该 Skill 做出来的真实作品画廊，并引导用户怎么样去购买和安装我的付费 Skill。
- **域名与网站部署（ [Cloudflare](https://www.cloudflare.com/) + [Vercel](https://vercel.com/) ）** ：我的域名是在 [Cloudflare](https://www.cloudflare.com/) 买的，一年大概 `10 美金` 左右；网站部署在 [Vercel](https://vercel.com/) 上，个人非商用免费（Hobby 档），商用最低档的 Pro 套餐是 `20 美金/月` 。
- **数据库与认证（ [Neon](https://neon.com/) ）** ：我的数据库用的是 [Neon](https://neon.com/) ，认证服务用的也是 [Neon](https://neon.com/) 。在用户量小的时候，它的免费额度基本就够用了，几乎是免费的。
- **邮件登录服务（ [Resend](https://resend.com/) ）** ：用户登录采用邮件验证码登录的方式，发邮件的平台使用的是 [Resend](https://resend.com/) 。它提供每月 3,000 封（每天上限 100 封）的免费额度，解除每日发送限制的付费 Pro 套餐是 `20 美金/月` （包含每月 50,000 封邮件）。
- **支付渠道（ [Stripe](https://stripe.com/) ）** ：支付渠道使用的是个人开发者也能低门槛开通的 [Stripe](https://stripe.com/) （具体开通与接入方法见 [《个人开发者收款指南》](https://book.oiloil.org/articles/indie-dev-stripe-payment) ）。Stripe 没有月租费，在没有交易量之前是不扣任何费用的，只有在成功收款时才会按笔扣除手续费（例如港区账户标准费率约为 `3.4% + HK$2.35/笔` ，美区账户约为 `2.9% + $0.30/笔` ，如涉及跨币种结算会额外收取 `1%–2%` 的货币转换费）。
- **CLI 鉴权与安装交付** ：交付付费 Skill 的方式是提供一个专门的 CLI 命令行工具（ [oil-cli](https://github.com/oil-oil/oil-cli) ）。用户在官网购买后，把安装命令发给本地 AI Agent 执行，这个 CLI 就会走我们官网的认证 API 进行登录鉴权（通过浏览器确认授权），校验通过后直接把付费版 Skill 下载并安装到位。
![付费 Skill 从场景切分单源构建、买断收款到 CLI 鉴权交付与静默更新的四步商业闭环](https://book.oiloil.org/assets/articles/commercial-paid-skill/02-paid-skill-closed-loop-v1.svg)

### 3\. 自动更新检查与双版本同步发版

除此以外，我还在 Skill 里面提供了一个 **自动更新检查的流程** （在 `SKILL.md` 开始前调用内置的 `check_update` 脚本）。

平时用户使用这个 Skill 时，脚本会在后台检查官网公开的最新版本号（设置了 10 分钟的检查间隔与 2 秒超时限制，不会拖慢正常任务；发现新版本时默认只在回复末尾提示更新命令，由用户确认后再通过 CLI 更新）。

我会不断地去迭代这个 Skill，然后在每一次发版的时候，将 Skill 一部分作为开源版本的发布，一部分作为付费版本的发布。发布之后，用户那边在使用时就能够收到新版本更新的通知——只要他日常有在使用，他就能清楚地知道这个产品是一直在持续迭代的。
